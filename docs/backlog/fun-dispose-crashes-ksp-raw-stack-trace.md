# `fun dispose()` crashes KSP with a raw stack trace instead of a diagnostic.

> Extracted verbatim from `ROADMAP.md` (Phase 5: Exception handling) in the 2026-08-31 roadmap slim-down.

**`fun dispose()` crashes KSP with a raw stack trace instead of a diagnostic.** `class Closer { fun dispose() {} }` aborts `NugetProcessor.process()` with `java.lang.IllegalArgumentException: Forward ABI duplicate C# import for closer_dispose` (`ForwardAbiContract.kt:76`). It fails safe (no invalid `Interop.cs` is written), but the failure is an unstructured JVM exception rather than a named `ForwardDiagnostic`. Same family as the constructor-collision item above: an always-emitted member, here `Dispose` from the generated `IDisposable` implementation, excluded from the collision set it should be checked against, so an ordinary Kotlin method whose name happens to collide with it aborts the whole KSP run instead of getting `ERROR_CSHARP_SIGNATURE_COLLISION` with a hint to rename it. `fun close()` is unaffected and renders `public void Close()` alongside `public void Dispose()`, so the collision is specifically the `dispose`/`Dispose` name pair. Discovered alongside the constructor reference-nullability fix above while verifying the always-emitted-member blind spot in ADR-034's fail-fast family; not fixed as part of that change since it is a distinct code path (method export, not constructor export).
