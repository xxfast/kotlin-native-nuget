TITLE: Bind a nullable `Flow` return and parameter on every owner (ADR-230)

The static flow route bound `Flow<T>`, but a nullable `Flow<T>?`, `StateFlow<T>?` or `SharedFlow<T>?` return or property on a top-level, `object`, companion, enum or value-class owner was still a `NULLABLE` drop. A `Flow<T>?` parameter was refused the same way on the plan and on the legacy `suspend` hosts. A return now reuses the class route's shape (a `_has_value` probe, then the ordinary lazy holder), and a parameter registers its source only when it isn't `null`, so a C# `null` passes a zero key and Kotlin gets `null`.

```kotlin
fun purrsIfHome(home: Boolean): Flow<Int>? = if (home) flowOf(1, 2) else null

suspend fun countVisitors(visitors: Flow<Int>?): Int = visitors?.toList()?.sum() ?: -1
```

```csharp
KotlinFlow<int>? purrs = Absences.PurrsIfHome(true);   // collects 1, 2
Assert.Null(Absences.PurrsIfHome(false));

await Doorways.CountVisitorsAsync(null);                // -1
await Doorways.CountVisitorsAsync(Of(1, 2, 3));         // 6
```

The C# parameter is `IAsyncEnumerable<int>?` and registers as `visitors is null ? IntPtr.Zero : NugetTasks.Register(...)`; on the Kotlin side the key slot is `COpaquePointer?` and a zero key builds no holder. `StateFlow<T>?` isn't an input, since the input route takes no `StateFlow` at all. A `suspend` member with a nullable flow result already bound, nothing changes there.

Fixes a trampoline bug on the way: `readThroughTrampoline` rebuilt a `FlowSource` from its element alone, so the generic-`T` trampoline dropped the flow's nullable flag (`suspend fun <T> firstOr(items: Flow<T>?, fallback: T)`).
