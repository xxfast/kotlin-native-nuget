TITLE: Bind a plain lambda on a `suspend` or `Flow` member (ADR-231)

A plain `(T) -> R` lambda parameter is call-scoped: C# registers the delegate's callback context and unregisters it in a `finally` once the P/Invoke returns. A `suspend` member returns long before its coroutine ends, and a `Flow` member's body runs during the collection, so that `finally` would free the context while Kotlin could still call the lambda. Both were dropped as `SKIPPED_UNSUPPORTED_INPUT`, for every payload and every owner. Now C# hands the key over to Kotlin, which releases it when the coroutine or the collection ends.

```kotlin
class Treadmill(val runner: String) {
  suspend fun run(steps: Int, onStep: (Int) -> Unit): Int {
    repeat(steps) {
      delay(1.milliseconds)
      onStep(it)
    }
    return steps
  }

  fun watch(laps: Int, onSeen: (Int) -> Unit): Flow<Int> = flow {
    repeat(laps) {
      onSeen(it)
      emit(it)
    }
  }
}
```

```csharp
await using var treadmill = new Treadmill("Oreo");
var seen = new List<int>();

int steps = await treadmill.RunAsync(3, seen.Add);               // 3, seen is [0, 1, 2]
using KotlinFlow<int> watching = treadmill.Watch(3, seen.Add);   // a fresh context per enumeration
```

The delegate lives until the `Task` settles (completion, fault or cancellation) or the collection ends (including `break` and `DisposeAsync()`). On a `suspend` member returning a `Flow` it lives as long as the returned `KotlinFlow`: disposing or finalizing it releases the context. A null delegate on a `Flow` member throws `ArgumentNullException` at the first enumeration, like every other `Flow` argument, not at the call.

A lambda returning an exported class (`make: (String) -> Baton`) now binds on every callback route, ordinary members included, which flipped two Tier 1 refusals (`pickToy` in `Tier1CallbackParameterPlanTest`, `makeCat` in `Tier1LegacyCallbackBuiltinPayloadTest`).

The launch uses `CoroutineStart.ATOMIC` so the release runs even on a cancellation before dispatch. That's from the kotlinx.coroutines docs; the collectability rows in `LeakTests` would catch it being wrong, but there's no dedicated test for it.
