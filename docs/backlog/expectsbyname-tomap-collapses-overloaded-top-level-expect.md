# `expectsByName`'s `.toMap()` can collapse overloaded top-level `expect fun`s onto one key

**`NugetProcessor.kt`'s `expectsByName` index (~lines 338-343) builds `Map<String, KSDeclaration>` keyed by qualified name via `.associateBy`/`.toMap()`** over every `isExpect` declaration; two overloaded top-level `expect fun`s with the same qualified name (same package, same simple name, different parameter lists) collapse onto one map entry, silently keeping whichever declaration iteration order visits last. [ADR-091](https://github.com/xxfast/kotlin-native-nuget/blob/main/docs/adr/091-constructor-default-parameters.md)/[ADR-096](https://github.com/xxfast/kotlin-native-nuget/blob/main/docs/adr/096-function-default-parameters.md)'s default-parameter lookup reads this index by qualified name to recover the `hasDefault` bit an `actual` can never restate, so an overloaded `expect fun` pair could have its default-parameter lookup silently read the *wrong* overload's defaults, synthesizing a wrong omitting overload rather than failing loudly. Verified by reading, not reproduced by a fixture: no fixture in the tree declares two overloaded top-level `expect fun`s. Discovered alongside [ADR-074](https://github.com/xxfast/kotlin-native-nuget/blob/main/docs/adr/074-expect-actual-declarations.md)'s 2026-09-05 amendment.
