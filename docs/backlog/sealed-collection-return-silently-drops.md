# A bare sealed-typed parameter vanishes from C# with no diagnostic

> Extracted verbatim from `ROADMAP.md` (Phase 3).

**A bare sealed type at a parameter position, `fun f(shape: Shape)` or a constructor with sealed-typed parameters, drops silently, with no diagnostic**, the same `ForwardPlanSkipReason.SEALED_PROTOCOL` (`droppedFromCSharp = false`) legacy-route deferral class that used to also cover every sealed *return*. The `#54` fixture's own generated output is the concrete evidence: `Issue54Drawing`'s primary constructor takes four sealed-typed parameters (`shape: Issue54Shape`, `maybe: Issue54Shape?`, `shapes: List<Issue54Shape>`, `current: Issue54Shape`), and the generated `Issue54Drawing` class carries only the always-emitted `internal Issue54Drawing(IntPtr handle)` wrapper constructor, no public one; the `packNuget` log for that fixture named all four *property* skips (pre-ADR-105) but named no constructor skip at all. Established by that fixture's generated output plus source reading, not chased.

**Shipped 2026-09-07:** the *return* half of this defect class ([ADR-009](docs/adr/009-sealed-class-mapping.md)'s amendment, composing [ADR-105](docs/adr/105-sealed-property-position.md)'s `sealedAsHandle()` rewrite) closed both the scalar case (`fun x(): Shape` on a class, object, or companion member) and the collection case (`fun x(): List<Shape>` at any callable position); both now bind through `FromHandle` exactly as a top-level bare sealed return always did. Since [ADR-064](docs/adr/064-forward-unsupported-declaration-diagnostics.md)'s 2026-09-07 amendment, a class left with no reachable public constructor (because every constructor parameter is sealed-typed, as above) also now warns once, naming every skipped constructor and its reason, though the per-constructor skip itself still carries no diagnostic of its own.

The parameter side above (a bare sealed parameter, or a constructor with sealed-typed parameters) is the half that remains open: it was never on ADR-105's route (property planner only) and the return-side fix did not touch parameters either.
