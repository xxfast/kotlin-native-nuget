# Supported Features

This is the catalogue of language features the bridge maps across the Kotlin/Native ↔ C# boundary — in **both directions** — and how. For the development roadmap (including what is not yet supported) see [ROADMAP.md](ROADMAP.md). For the reasoning behind each mapping follow the ADR links in the last column.

**Direction** (the middle column of every table):

| Glyph | Meaning                                                                               |
|-------|---------------------------------------------------------------------------------------|
| `→`   | Kotlin → C#: a Kotlin feature you author, surfaced as C# (forward, code generation)   |
| `←`   | C# → Kotlin: a feature from a consumed C# NuGet package, surfaced as Kotlin (reverse) |
| `⇄`   | both directions                                                                       |

`⇄` is the target state. Where a row is one-way, the **Notes** say why — either it is **fundamental** (the reverse direction reads a compiled assembly you don't own, so some source-only Kotlin concepts can't round-trip), or it is simply **not built yet** (see [ROADMAP.md](ROADMAP.md)).

**Notes**

- **`[1]`** ← `Nullable<T>` is deferred: it needs its own wire format.
- **`[2]`** ← `NullableAttribute` byte 2 → `String?`, byte 1 → `String`, byte 0/oblivious → `String` (with an `info_oblivious_nullability` warning).
- **`[3]`** → Every `char` slot the generator emits, old and new, carries `[MarshalAs(UnmanagedType.U2)]`. This is a fix, not just an addition: the shipped `[DllImport]` had no `CharSet`/`MarshalAs`, which defaults to `CharSet.Ansi` and silently truncated any non-ASCII character to one byte with no exception (`Tag('é')` arrived Kotlin-side as `'Ã'`; a `Char` return or property getter for a non-ASCII value came back as `U+FFFD`). ASCII call sites are byte-identical; non-ASCII call sites go from corrupt to correct. This changes behaviour on already-shipped members, so anything relying on the truncated byte was already broken. A bare `Char?` (not inside a collection) still has no wire, since it needs a has-value fan-out `hasValueFanOutInner()` doesn't have yet, not a width fix; a lone surrogate `Char` (an unpaired `\uD83D`-style code unit) does not round-trip under any wire shape and is out of scope, since neither a Kotlin `Char` nor a C# `char` can legitimately hold one.

**Notes**

- **`[1]`** ← The `GCHandle` is released via `Cleaner` (deterministically via `close()` / `use {}`). C# statics land in a `companion object`, instance members on the wrapper. An instance member colliding with the wrapper's own `handle`/`close`/`cleaner` is skipped with a warning. Object return/param nullability is metadata-driven per `NullableAttribute` (`Foo` vs `Foo?`); a new wrapper is created per crossing (identity equality, no caching).
- **`[2]`** ← Overloads retain their parameter types and use signature-derived internal bridge identities.
- **`[3]`** → Object methods behave exactly like class methods (e.g. a `String` return → `string`).
- **`[4]`** ← Only public top-level, default-`int`, non-`[Flags]` enums with unique contiguous `0..N-1` values. Nullable, nested, sparse, aliased, collection, and generic enum positions are not built yet.
- **`[5]`** Two shapes share one wire format and `data class` surface. **Shape A**: exactly one state-covering constructor whose parameters define the components, in constructor order. **Shape B**: no such constructor (public settable fields and/or `set`/`init` auto-properties); components come from C# declaration order and reconstruct with an object initializer (`new T { A = a, B = b }`) rather than `new T(a, b)`, binding no constructors at all. Alternate public constructors (Shape A only) become Kotlin secondary constructors backed by out-pointer bridge slots. Instance methods and get-only non-component computed properties land on the `data class` (reconstruct-on-call: N component wire args first); static methods land in a `companion object`. A component may itself be a struct at any depth: the wire flattens it recursively, depth-first pre-order (ABI name is the `_`-joined path) while the Kotlin surface stays nested, so structural equality and `copy()` compose across the nesting; all four Shape A/B nesting combinations work, including across a Kotlin package boundary. A member whose flattened ABI arity exceeds Kotlin/Native's 22-argument `CFunction.invoke` ceiling is skipped with a `skipped_abi_arity_limit` diagnostic. Class-typed components, generic structs, structs in collections, alternate constructors, and manual (non-auto) settable properties on a Shape B struct stay deferred.
- **`[6]`** → Only reachability-driven: the backing class and its `foo_*` dispatch exports are generated only for interfaces that actually appear in a planned return position; `IFoo` itself is still emitted unconditionally. Each interface-typed return mints a fresh handle, resolved back to its original C# object first when one exists (see `[10]`), otherwise a `new Foo(handle)` wrapper (no identity caching for a Kotlin-backed object, per ADR-005).
- **`[7]`** ← A different feature from `[6]`, not its other direction: here C# owns the interface. An interface-typed value (return, parameter, or property) received from C# always binds as `IFooHandle`, never the concrete bound class, even when the runtime object is itself bound; no downcast, no `QueryInterface`. `ITagged : IFeedable`-style interface inheritance binds unconditionally when the base interface is itself admissible and bound. Passing a bound class at an interface-typed parameter goes through a `NugetHandleOwner` marker, the mirror of the forward direction's `NugetMarshal.HandleOf`. **Passing a Kotlin *implementation* of the interface back to C# is now supported too** ([ADR-085](docs/adr/085-kotlin-implemented-csharp-interfaces.md)): `NugetGenerateShimsTask` emits a C#-side bridge class (`IFeedableBridge`) per admissible bound interface, holding one Kotlin-minted `staticCFunction` function pointer per member plus a ctx `StableRef`; a plain Kotlin class with no `NugetHandleOwner` mints one through a factory thunk instead of hitting the old `error(...)`. v1 slot vocabulary: `val`/`var` property getter-and-setter slots, and arity 0-2 methods returning `Unit`/primitive/`Boolean`/enum/`String`/`String?` (the same vocabulary as `[10]`, extended to cover setters). Lifetime is inverted from `[10]`: a C#-side `SafeHandle` releases the Kotlin `StableRef` when the .NET GC collects the bridge; the Kotlin-side transfer handle is freed immediately after the call. Identity is Kotlin-side only (`assertSame(goat, sanctuary.featured)`), the mirror of `[10]`'s C#-side-only identity. **Repeated crossings of the same Kotlin object now resolve to the same C#-side bridge instance, while it stays alive** ([ADR-089](docs/adr/089-bridge-reuse-per-kotlin-object.md)): each `{Iface}Bindings.kt` gains an identity-keyed table (`kotlin.native.identityHashCode`) holding the bridge weakly, so `ReferenceEquals` now holds for a live bridge; once C# drops every reference and the .NET GC collects it, the next crossing mints fresh, superseding the original "one bridge per crossing, no reuse table" posture for the live case. Skipped and diagnosed rather than silently dropped: generic interfaces, `static`/`static abstract`/`static virtual` interface members, indexers, events, and an interface with zero admissible members. **A Kotlin class implementing more than one bound interface now dispatches correctly:** `nugetMintBridge` keys on the crossing position's fully qualified interface name rather than a first-match `is` check, so `RingLeader : IFeedable, IPerformer` mints the bridge each interface-typed parameter actually asks for (ADR-085 addendum). **A Kotlin implementation of a *derived* interface now binds too** ([ADR-086](docs/adr/086-object-interface-slots-kotlin-bridge.md) addendum to ADR-085): `Tabby : ITagged` mints one flattened factory covering `ITagged`'s own slots plus everything it inherits from `IFeedable`, base emitted before derived, diamond- and `new`-redeclaration-deduped; the interface's contract hash now covers that flattened, ordered slot signature list rather than only its own registration slots, closing a silent-ABI-drift hole the base ADR had flagged but not yet closed for the derived case. **Bound-object-handle and bound-interface members now bind at a slot too** ([ADR-086](docs/adr/086-object-interface-slots-kotlin-bridge.md)): parameters, returns, and getter/setter properties, nullable included, on one ownership rule, the side receiving the handle owns it: a parameter transfers ownership to Kotlin, while a return or getter is always a fresh transfer handle (a per-interface `dupHandleFn` thunk) the C# bridge member resolves and frees immediately. Still out of v1 and named-skipped (`skipped_kotlin_bridge`): a struct-typed slot, a generic-instance slot, a collection-typed slot (`List`/`Map`/`Set`, blocked on the reverse direction having no BCL collection mapping at any position yet), and a `Task`-typed member. **A thrown exception inside a member is now catchable from C# too, with one boundary** ([ADR-087](docs/adr/087-kotlin-slot-exceptions.md)): every slot carries a trailing error out-parameter that writes a Kotlin-owned envelope on a throw, and the C# bridge member throws the same public `KotlinException` family a forward call throws, but only when C# calls the bridge member directly; a call that *originates* in Kotlin and reaches the same member indirectly through an ordinary reverse-bound method still terminates the host, since that outer call's own `[UnmanagedCallersOnly]` reverse thunk has no error path of its own yet (ROADMAP Phase 11).
- **`[8]`** → A bare `Nullable(Enum)` (`Mood?`, not wrapped in a value class) binds at property (class, companion, top-level, extension), constructor/method/extension/top-level parameter, method return, and top-level return, riding the same has-value wire shapes as `Nullable(ValueClass)` over an `Enum` underlying (see [Value classes](docs/topics/value-classes.md#nullable-over-primitive-and-enum-underlyings)) with the box/unbox step removed: the wire is already the `int` ordinal. Nullable enum as a collection component is a distinct, separately-shipped feature, see `[13]`.
- **`[9]`** → A top-level `actual fun`/`val` takes its generated C# static class name from the **expect's** file, not the actual's, so per-target actual files with different names don't produce two differently-named C# classes for one Kotlin declaration. `actual typealias Foo = Target` erases `Foo` entirely; every reference to it redirects to `Target`'s own C# type, with `SKIPPED_ACTUAL_TYPEALIAS_TARGET` when the target isn't itself exportable. `expect sealed class`, a generic/parameterized `actual typealias` target, and cross-module `expect`/`actual` are deferred.
- **`[10]`** → Closes the old v1 boundary: a C# class implementing a Kotlin `interface` (no `_handle`) can now be passed at an interface-typed parameter or property setter; `NugetMarshal.HandleOf` falls back to a per-interface bridge factory export (`pet_bridge_create`) instead of throwing `NotSupportedException`. v1 slot vocabulary is `val` getters and methods of arity 0-2 returning `Unit`, a primitive, `Boolean`, an enum, `String`, or `String?`; an interface with a `var` property, or any other out-of-scope member, plans no factory at all and keeps the old throw, silently (no diagnostic yet). Lifetime is a Kotlin-side `createCleaner` invoking a C#-supplied release function pointer when Kotlin's GC collects the bridge, so release is GC-timed, never prompt. A stored C#-implemented object returned back to C# resolves to the original instance via a token probe (`Assert.Same` holds), C#-side identity only; Kotlin-side `===` across repeated crossings of the same C# object is not preserved, since each crossing builds its own bridge object rather than reusing a cached one.
- **`[11]`** → [ADR-088](docs/adr/088-kotlin-implemented-interfaces-at-forward-positions.md): the ADR-070 pure interface stub, previously always `internal`, is now public exactly when nothing in its declared surface (or a base interface's) is an internal bound-class/struct/generic-instance stub, so a Kotlin author's own public API can name it in a signature. A new cross-pipeline manifest (`bound-types.json`) carries each admissible interface's original C# name and ADR-085 Kotlin-implementability from the plugin into the KSP processor, since the existing `nuget.boundPackages` flat package list can't invert to it. Wire: the reverse pipeline's own GCHandle machinery both ways (`nuget{Iface}Value` in, `dupHandleFn` out). v1: non-nullable, ordinary parameters and method/top-level-function returns only; nullable, property, and collection-component positions are a named `SKIPPED_BOUND_TYPE_POSITION` skip; a return of a plain Kotlin implementation of a non-Kotlin-implementable interface is `SKIPPED_UNIMPLEMENTABLE_BOUND_INTERFACE` (unreached by this project's own fixtures today, since every bound interface here is Kotlin-implementable). Bound **classes** at forward positions stay out of scope.
- **`[12]`** → [ADR-091](docs/adr/091-constructor-default-parameters.md): KSP exposes only `hasDefault`, never the value, so the synthesized overload's Kotlin wrapper calls the constructor positionally with fewer arguments and Kotlin supplies the rest at the call site; the C# side never sees a default expression. Applies to primary and secondary constructors; for an `expect`/`actual` pair the bit is read off the `expect`'s primary constructor via the `expectsByName` index, since Kotlin forbids an `actual` from restating a default (an `expect` class's secondary constructors get no overloads in v1). A synthesized overload colliding with a real or another synthesized constructor fails generation with `ERROR_CSHARP_SIGNATURE_COLLISION`. Out of scope: value-class constructor defaults (a separate numbering space, ADR-035) and partial `Copy(...)` overloads (the `COPY`-origin plan already means "current value", not "constructor default"); function/method default parameters use the same mechanism and are now covered by [ADR-096](docs/adr/096-function-default-parameters.md), see the Functions & Lambdas table.
- **`[13]`** → A bare enum component (element, map key, or map value, nullable included) at a `List`/`Map`/`Set` input position, a collection property setter, a method return, or a property getter crosses as its `int` ordinal, projected per element at the C# call site (`Select(x => (int)x)`) and re-wrapped in Kotlin (`Mood.entries[it as kotlin.Int]`), generalizing the value-class-over-enum wire [ADR-081](docs/adr/081-value-class-collection-components.md) already shipped one level down. Closes a shipped bind-then-throw defect on **both** directions (write side had no `Wrap<T>` branch; read side's `FromHandle<Mood>` had no `Materialize` route). `List`'s callable-input gate narrows from `isBridgeableComponent()` to `isWrappableComponent()` in the same change, see the Collections table's `[1]`.
- **`[14]`** → [ADR-101](docs/adr/101-unexported-supertype-skip.md): `CirClassTranslator`'s `interfaces` list is filtered against the qualified-name-keyed `exportedTypes` before the `I`-prefix step; an interface outside the export set is dropped and named in a `SKIPPED_UNEXPORTED_SUPERTYPE` warning instead of rendering a base-list entry nothing generates (`CS0246`). Interface supertypes only: an unexported **base class** (`class X : UnexportedBase()`) dangles the same way and is not yet covered, since the fix would need to thread the export set through the shared `forwardSuperClass()` predicate and all four of its call sites, not just the translator. The `include(...)` hint `SKIPPED_UNEXPORTED_DEPENDENCY_TYPE` gives does not apply here and is deliberately not reused: the ADR-066 reachability closure has no edge for supertypes, so admitting the dependency package would not change the outcome.

**Notes**

- **`[1]`** ← Instance or static; static properties live in a Kotlin `object` or `companion object`. A settable handle-typed property renders as `var Foo` / `var Foo?` per its `NullableAttribute`, getter and setter sharing one type.
- **`[2]`** Nullable numeric uses a single call (`bool` has-value + `valueOut` out-param): a method may have side effects and can't be invoked twice.
- **`[3]`** A value-class receiver crosses as its underlying wire value and is re-wrapped with the value class's own constructor before use, same treatment as an ADR-077 value-class parameter. No dedicated ADR: a mirror of ADR-077's lowering applied at the receiver slot. **`[1]`** `Map`/`Set` parameters, and a value-class component at any `List`/`Map`/`Set` position (element, key, or value, including a `List` parameter, per [ADR-081](docs/adr/081-value-class-collection-components.md)), bind only for the C#-boxable set: `String`, `Int`, `Long`, `Float`, `Double`, `Boolean`, `Byte`/`UByte`/`Short`/`UShort`/`UInt`/`ULong`, `Char`, an object handle, a bare enum (riding its `int` ordinal, per [ADR-097](docs/adr/097-enum-collection-components.md)), a `List`/`Map`/`Set` itself (nested, per `[10]`), or a value class over one of the first four underlyings (an enum-underlying value class rides the enum's `int` ordinal too). The six narrow primitives and `Char` were the last scalar gap in that set, closed by [ADR-098](docs/adr/098-narrow-primitive-and-char-collection-components.md): six new `nuget_wrap_*` exports for the primitives, plus `nuget_wrap_char`/`nuget_unwrap_char` and `[MarshalAs(UnmanagedType.U2)]` for `Char` (see the Primitives table's `Char` row `[3]`). A *nullable* spelling of any of those (element, set member, or map **value**) also binds, riding a null pointer in the component slot with no has-value pair, on both the write and read side, per [ADR-083](docs/adr/083-nullable-collection-components.md); a nullable bare enum element (`List<Mood?>`) is admitted the same way by ADR-097's `Nullable` delegation, and a nullable narrow-primitive element (`List<Short?>`) the same way by ADR-098's. A **nullable nested collection** (`List<List<String>?>`) is the one component shape that stays a named `SKIPPED_UNSUPPORTED_INPUT` skip, deliberately, per `[10]`; an interface component still skips too. A nullable map **key** is the one nullable spelling that stays a named skip (a C# `Dictionary` can't hold a null key). `List`'s input gate is the same `isWrappableComponent()` predicate `Map`/`Set` use, narrowed from a wider, pre-ADR-097 gate that let `Char`/narrow-primitive/nested-collection `List` parameters bind and then throw or crash `packNuget`; every C# member lost by that narrowing previously did one of those two things, never a member that worked. Method returns and property getters with a value-class, bare-enum, narrow-primitive, `Char`, or nested-collection component also bind correctly today; a bind-then-throw defect on that read side is fixed by ADR-081 (value class), ADR-097 (bare enum), ADR-098 (narrow primitives and `Char`), and ADR-099 (nested collection), and the equivalent bind-then-NPE defect for a nullable component on any returned collection is fixed by ADR-083.

**`[9]`** A `var` collection property's setter binds only when every component (the element for `List`/`Set`, the key **and** value for `Map`) satisfies the same `isWrappableComponent()` predicate as `[1]`, applied to `List` as well, including its nullable-component, bare-enum, narrow-primitive/`Char`, and nested-collection widening. An ineligible component keeps the property get-only in C# and emits a `SKIPPED_UNSUPPORTED_INPUT` diagnostic naming it. The getter is unconditional and has no element-type restriction; only the setter is narrowed. The collection reference's own nullability (`List<T>?`) is independent of its components' marshallability and always gets both a getter and (when eligible) a setter.

**`[10]`** A component itself typed `List`/`Map`/`Set` (nested, arbitrary depth, every outer/inner kind combination) crosses as the **inner collection's own native handle**, in the same pointer-shaped component slot every other component already uses: no new native export, no ABI change. `CreateList<IntPtr>(rows.Select(x => CreateList<string>(x)))`-shaped write side; a matching `finally`-guarded `ReadList`/`ReadSet`/`ReadMap` read side. Closes a shipped bind-then-throw landmine on the *return* side: `fun grid(): List<List<String>>` bound and compiled before [ADR-099](docs/adr/099-nested-collection-components.md), then threw `NotSupportedException` out of `FromHandle<T>` at the first element read rather than at the call, so a consumer saw a partially-executed method. `List<List<String>?>`, a nullable **nested collection**, stays a named `SKIPPED_UNSUPPORTED_INPUT` skip: admitting it through the same `Nullable` delegation `[1]`'s leaf nullability uses would bind a write projection with no null arm. A nullable **leaf** under nesting (`List<List<String?>>`) is admitted and rides `[1]`'s existing nullable-component wire one level down.

See [ADR-011](docs/adr/011-collection-type-mapping.md), [ADR-062](docs/adr/062-forward-callable-plan.md), [ADR-073](docs/adr/073-map-and-set-parameters.md), [ADR-075](docs/adr/075-collection-property-getter-setter-independence.md), [ADR-081](docs/adr/081-value-class-collection-components.md), [ADR-083](docs/adr/083-nullable-collection-components.md), [ADR-097](docs/adr/097-enum-collection-components.md), [ADR-098](docs/adr/098-narrow-primitive-and-char-collection-components.md), and [ADR-099](docs/adr/099-nested-collection-components.md).
