# The forward processor has almost no unit-test seam.

> Extracted verbatim from `ROADMAP.md` (Tooling & Test Integrity) in the 2026-08-31 roadmap slim-down.

**The forward processor has almost no unit-test seam.** `nuget-processor/src/test` holds two files (`CirFunctionTranslatorNullableTest`, `ForwardAbiContractTest`) against nine for the reverse `nuget-plugin`. The fast inner loop reverse work takes for granted — a fixture in, expected generated text out, asserted in seconds — does not exist forward: every iteration on a translator or renderer is a full `packNuget`. Not a bug, a cost, and worth weighing before the Phase 2–6 items above are worked, since they are four codegen fixes in a row through that loop. Plausibly also part of why they went unseen: the reverse generators got unit-tested into existence, the forward ones were only ever observed through a full round trip. Note the complement already tracked below — the reverse direction lacks a *compile* check on its generated Kotlin, while the forward direction gets one free (its `CNameExports.kt` is compiled by `:test-library:compileKotlinMingwX64`), which is why the Phase 4 value-class and collection items surface as build breaks rather than silent text. **Partly closed by [ADR-060](docs/adr/060-adversarial-forward-fixture.md)'s Tier 1 harness**, which is exactly this fast inner loop for the slice it needs — "Kotlin source in → real `NugetProcessor` → generated `CNameExports.kt` compiled in-process", red in ~sub-second per cell after warmup — and is the loop each of the four upcoming forward codegen fixes runs through. It is **not** the item's full ask: a fixture-in/expected-generated-text-out unit suite for every translator and renderer still does not exist, so this stays open; the harness closes only the compile-the-generated-Kotlin slice the codegen fixes depend on. **Further paid down by [ADR-064](docs/adr/064-forward-unsupported-declaration-diagnostics.md)**, which adds the harness's diagnostic-assertion mode's first real coverage for the *diagnostics* slice: `Tier1DiagnosticCellsTest` (cells 21, 23) and `Tier1NamedSkipDiagnosticsTest` (Map/Set input, nullable Boolean return, value-class inherited members) assert the exact `ForwardDiagnosticKind` fires and that no broken source is emitted. Still not the item's full ask: the translator/renderer fixture-in/expected-text-out suite remains absent outside the diagnostic and compile slices
