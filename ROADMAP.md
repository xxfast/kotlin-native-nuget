## First stable release (1.0.0)

Two minor releases lead to 1.0.0: 0.9.0 carries every breaking change, 0.10.0 is hardening and acts as the release candidate, and 1.0.0 adds policy and docs with no breaks. Scope agreed 2026-09-29, after the 0.8.0 release; a claim below is verified (read in code or spiked) or inferred (not run), as labelled. An item that would force a semver-major after 1.0.0 lands in 0.9.0; additive work stays in its phase below and ships in 1.x. At 1.0.0 the forward direction (Kotlin to C#) is stable, and semver covers the Gradle DSL, the task names, the fixed generated C# types, the `nuget_*` runtime ABI, the diagnostic codes and `NugetDiagnostics.json`. The reverse direction (C# to Kotlin) is experimental behind an opt-in and may break in 1.x: it binds 34.0% of public members over nine real packages (`nuget-plugin/src/test/resources/dogfood/SUMMARY.md`) and its output has never been compiled against one. The Maven artifact ids stay `nuget-plugin`, `nuget-processor` and `nuget-runtime`.

## Phase 8: Ecosystem – consuming NuGet packages from Kotlin

The inverse of everything above, modeled on the Kotlin CocoaPods plugin: resolve a C# NuGet dependency, extract its public API from .NET assembly metadata, generate Kotlin-idiomatic bindings. Kotlin → C# calls need no CLR hosting (the host process is always .NET; the generated C# side registers function-pointer thunks with Kotlin at startup). Research: [synthesis + candidate ADRs](docs/research/nuget-plugin-architecture-synthesis.md).

- [ ] `packNuget` should warn when a bound dependency was restored from a local source, since the packed shim then pins a version no feed serves (deferred by [ADR-190](docs/adr/190-local-nupkg-dependency-source.md); fails loudly in the consumer as `NU1101` today).
- [ ] A lazy file source with task-dependency inference (`source` fed from another task's output) is unverified; today the path is a plain string resolved at wiring time ([ADR-190](docs/adr/190-local-nupkg-dependency-source.md)).
- [ ] The project-local packages folder applies only when a local source is declared; making it universal is undecided ([ADR-190](docs/adr/190-local-nupkg-dependency-source.md)).
- [ ] A per-dependency `source` is not exclusive for its package id; shared and per-dependency feeds are a union, so which feed serves an id held by two remote feeds is unspecified. Candidate: package source mapping in a generated `NuGet.Config` ([ADR-191](docs/adr/191-shared-feed-list.md) keeps the spike findings). Blocked on a spike against an authenticated feed, because `packageSourceCredentials` are keyed by source name and a generated config may drop the user's credentials (unverified).
- [ ] Reverse diagnostics are silent on an `UP-TO-DATE` `nugetGenerateBindings` (the `build/nuget-interop/NugetDiagnostics.json` file survives); candidate fix is the single-voice move of the log to `nugetReportDiagnostics` ([ADR-182](docs/adr/182-public-naming-scheme.md) alternative A). Needs a real two-run build log for a bind-only and a publish-plus-bind project, the failed-finalized-task case, proof `nugetImport` does not start KSP (hazard: `nugetReportDiagnostics` depends on `kspKotlin{Target}`, `NugetPlugin.kt:574`, so wiring it to `nugetImport` would run KSP on every IDE sync), and a decision on per-build line volume (2,300+ diagnostics over nine dogfood packages).
- [ ] Emit `SKIPPED_INTERFACE_SUPERTYPE` and `INFO_INHERITED_INTERFACE_MEMBERS_ABSENT` (nothing constructs them; drops are at `rir/RirBridging.kt:84` and `:120-123`, and `TestDependency/Menagerie.cs:104-109` class `Shy` expects the diagnostic and gets nothing), then empty `RirDiagnosticCoverageTest`'s `notYetEmitted` set. The INFO kind may need a reader change: ADR-070:302-304 says the reader already filters `interfaces` to bound ones.
- [ ] Reverse diagnostics report follow-ups, undecided: one merged report or a `direction` field for both directions, `reason`/`hint` fields, a per-package split, a fail-on-skip gate, and `SKIPPED_KOTLIN_BRIDGE` granularity if the census shows it is loud.
- [ ] `alias` is exact while `includeNamespaces` is a prefix, so an admitted sub-namespace silently falls back to `packageName`; prefix matching is an open gap ([ADR-192](docs/adr/192-reverse-namespace-groups-via-alias.md)).

Post-goal expansion of the bridgeable subset is broken out into Phases 9–13 below, mirroring the forward-direction arc (Phase 3 → 7): basic types, rich types, exceptions, async, then bidirectional contracts.

## Phase 9: Reverse basic type support – C# objects in Kotlin

Mirror of Phase 3. Moves the reverse bridge beyond v1 static methods: C# objects become Kotlin classes backed by opaque handles, over the same ADR-041 registration table. All constructs here are already present in `reverse-ir.json` (ADR-046) or are small extraction additions – this phase is primarily stub-gen + shim-gen coverage, relaxing the ADR-043 v1 ceiling construct by construct.

- [ ] `Nullable<T>` value types (`int?`) are a different, deferred feature (ADR-053 Decision 3): no `NullableAttribute` machinery applies. The same gap blocks a nullable *value* element on the reverse async-enumerable route (`IAsyncEnumerable<int?>`, fixture `Kennel.NullableTicks()`): `RirPrimitiveType` carries no nullability at all, so it stays a named skip rather than binding as `Flow<Int>` and dropping the nulls. Discovered alongside [ADR-156](docs/adr/156-iasyncenumerable-to-flow.md). ([details](docs/backlog/nullable-t-value-types-int-different-deferred.md))
- [ ] Alternate constructors on a Shape B struct: diagnosed, not bound, since the struct's object-initializer primary already reaches every component and an alternate would collide with it. Deferred by [ADR-058](docs/adr/058-csharp-shape-b-structs-in-kotlin.md) Decision 4a; needs a rule for the primary-constructor collision before it can bind
- [ ] Manual (non-auto) settable properties as Shape B components ([details](docs/backlog/manual-non-auto-settable-properties-shape-b.md))
- [ ] Shape A constructor-parameter nullability decoding, a pre-existing ADR-056 gap ([details](docs/backlog/shape-a-ctor-param-nullability-decoding.md))
- [ ] Raising the 22-argument ceiling: pass a pointer to a packed scratch buffer once a member's flattened arity exceeds 22, instead of skipping the member. Sketched, not decided: needs its own call on buffer ownership, layout, and alignment (deferred by [ADR-059](docs/adr/059-nested-struct-components-in-kotlin.md) Decision 5d)
- [ ] `Nullable<T>` components, including a nullable *nested* struct (e.g. `Profile?` inside `Litter`): the existing struct out-pointer + `byte hasValue` format (see the `Nullable<T>` value types item above) extends to it without a new wire format, but it stays its own ROADMAP slice (deferred by [ADR-059](docs/adr/059-nested-struct-components-in-kotlin.md) Scope)
- [ ] Class-typed (handle) components inside a struct: deferred on semantics, not cost. ([details](docs/backlog/class-typed-handle-components-inside-struct-deferred.md))
- [ ] An interface member returning an interface from another bound namespace has no cross-package `nuget{Name}Value` resolver import on the bound-**interface** route (the class route was fixed alongside the init-only/cross-namespace compile-break fix); inferred, no fixture. ([details](docs/backlog/interface-route-cross-namespace-interface-return-import.md))
- [ ] The same cross-package resolver import is missing on the generic-witness route (`genericWitnessObjectFileContent`); inferred, no fixture. ([details](docs/backlog/generic-route-cross-namespace-interface-return-import.md))
- [ ] Two same-named types from two namespaces that resolve to one Kotlin package silently overwrite each other's generated file (`NugetGenerateBindingsTask.kt` writes with a plain `writeText`, `qualifiedTypeNames` only qualifies same names across packages); already true of the default config that flattens every namespace into one package. Verified by reading, no fixture. See [ADR-192](docs/adr/192-reverse-namespace-groups-via-alias.md).
- [ ] An `init`-only computed property on a Shape B struct is silently unbound instead of admitted as a getter (the reader's struct branch shares the writable-setter assumption the class/interface fix corrected); verified by reading only. ([details](docs/backlog/shape-b-struct-init-only-computed-property-unbound.md))
- [ ] `toMethodCamelCase` turns `URLPath` into `uRLPath` for every reverse method and property name; same acronym-run rule as the enum fix (ADR-006 2026-10-02 amendment).

## Phase 10: Reverse rich type support

Mirror of Phase 4: generics, collections, delegates, and the C#-specific surface sugar that has a direct Kotlin idiom.

## Phase 11: Reverse exception handling

Mirror of Phase 5. [ADR-104](docs/adr/104-reverse-thunk-error-channel.md) shipped the channel: any
managed call can throw and the exception now reaches Kotlin as a catchable
`NugetManagedException(managedType, message)` instead of a fatal `[UnmanagedCallersOnly]` escape.
The four remaining items below are deliberately deferred (Fork B); each is now purely additive
under ADR-104's design, one or two more runtime accessor slots, never touching thunk arity or the
per-type contract hash again.

- [ ] Map core .NET exceptions to Kotlin analogs (`ArgumentException` → `IllegalArgumentException` etc. – ADR-029's table, reversed). Additive: more `managedErrorKind` values decided with an `is` test on the C# side (ADR-153's mechanism; a name match over `managedType` misses a subclass, e.g. of `OperationCanceledException`, so it's not the route)
- [ ] Propagate the .NET stack trace on the Kotlin exception (mirror of ADR-027). Additive: one more runtime accessor slot plus one field, per ADR-104 Fork B
- [ ] Map `InnerException` → Kotlin `cause` chain (mirror of ADR-028). Additive: a `count`/indexed accessor pair mirroring `nuget_kotlin_error_cause_*`, per ADR-104 Fork B
- [ ] Propagate property accessor and constructor exceptions (mirror of ADR-030/031). The channel already carries these (getter/setter and constructor thunks all gained `errOut`); this line tracks the remaining ADR-029/027/028-equivalent fidelity (typed mapping, stack trace, cause chain) for those call shapes specifically

## Phase 12: Reverse async support

Mirror of Phase 6.

- [ ] Map C# events → Kotlin (`Flow<T>` or listener + `Cleaner`-scoped subscription; no forward-direction mirror exists – needs ADR, builds on [ADR-158](docs/adr/158-reverse-delegate-parameters.md)'s one-slot delegate bridge and `RirDelegateType`)
- [ ] `ValueTask` / `ValueTask<T>` → `suspend fun`: named skip `info_async_not_yet_mapped` today; additive on top of [ADR-152](docs/adr/152-task-to-suspend-fun.md), one `RirAsyncKind` value plus `.AsTask()` in `Begin`.
- [ ] Async on a struct method, a bound interface member, or a generic class (witness thunks) is a named skip (`asyncDeferredDiagnostics`), covering `IAsyncEnumerable<T>` the same way as `Task`/`Task<T>` since [ADR-156](docs/adr/156-iasyncenumerable-to-flow.md); `Task` at a parameter, property, constructor, or type-argument position, and a `Task<T>?` return, are reader-side `info_async_not_yet_mapped`. Deferred by [ADR-152](docs/adr/152-task-to-suspend-fun.md). `Task<TCollection>` (a `Task` returning a BCL collection) is deferred the same way by [ADR-155](docs/adr/155-csharp-collections-in-kotlin.md).
- [ ] A **sync** method taking a `CancellationToken`, a method taking two or more, a nullable `CancellationToken?`, and a token on a constructor or property stay named-skipped `info_cancellation_token_not_yet_mapped` rather than bound. Deferred by [ADR-153](docs/adr/153-reverse-cancellation-token.md).
- [ ] Surface a caller-supplied cancellation handle for a C# API that stores its `CancellationToken` beyond the call (a constructor or property token), rather than the bridge always minting and owning its own. Deferred by [ADR-153](docs/adr/153-reverse-cancellation-token.md).

## Phase 13: Reverse bidirectional – implementing C# contracts in Kotlin

Mirror of Phase 7, composed with its machinery.

- [ ] Kotlin subclassing C# **classes** – explicitly deferred, revisit only with a concrete use case (synthesis D5, Swift-export precedent)
- [ ] `IAsyncEnumerable<T>` at a **parameter** position (Kotlin `Flow<T>` → C#). Named skip `info_async_not_yet_mapped` today, asserted by `NugetExtractApiIntegrationTest`. Blocked on a repeated-callback mechanism the reverse bridge doesn't have: its completion machinery is exactly-once (`NugetAwait.kt:23-47`); see [ADR-156](docs/adr/156-iasyncenumerable-to-flow.md)'s Alternatives.
- [ ] **Collection-typed slots for a Kotlin-implemented C# interface.** No longer blocked on the reverse collection wire, which [ADR-155](docs/adr/155-csharp-collections-in-kotlin.md) now ships (a slot buffer, reused as-is); today such a slot is a named skip (`skipped_kotlin_bridge`/`skipped_collection_position`). The inversion itself is unverified: it needs Kotlin to allocate with the allocator C# frees (`malloc` on Unix, `CoTaskMemAlloc` on Windows, the expect/actual mirror of `freeManagedString`). ([details](docs/backlog/collection-typed-slots-kotlin-implemented-c-interface.md))
- [ ] **`Task`-typed members on a Kotlin-implemented C# interface.** Deferred to compose with [ADR-152](docs/adr/152-task-to-suspend-fun.md)'s reverse async work; a `Task`/`Task<T>`-returning interface member is out of the v1 slot vocabulary and named-skipped. Also covers async delegate parameters (`Func<Task>`, `Func<Task<T>>`, `Func<CancellationToken, Task<T>>`), named `skipped_delegate_signature` since [ADR-158](docs/adr/158-reverse-delegate-parameters.md): both need the same missing piece, a Kotlin-to-C# completion mechanism (a `TaskCompletionSource` driven from a Kotlin callback) that nothing today provides.
- [ ] **Whether Kotlin frees an ADR-088 bound-interface transfer `GCHandle` when the callee throws is unverified either way.** ([details](docs/backlog/whether-kotlin-frees-adr-088-bound-interface.md))

## Phase 14: Runtime library – ship the fixed `nuget_*` ABI once

Everything but the C# twin has shipped: bullets 1 to 3 in [ADR-127](docs/adr/127-nuget-runtime-library.md) (the `nuget_*` ABI now lives in a versioned `nuget-runtime` Kotlin/Native library the plugin adds as `api` and `export()`s on every `SharedLibrary`, and the generator emits only the per-declaration part), a 67th export `nuget_runtime_version` ([ADR-129](docs/adr/129-nuget-runtime-version-export.md)), the runtime's `nuget_*` exports verified on the Windows (mingwX64) leg (ADR-127), the reverse bridge's error envelope folded onto the runtime's own `NugetError` ([ADR-130](docs/adr/130-reverse-error-envelope-on-runtime.md)), and the generator adopting the runtime's `launchForCSharp`/`collectForCSharp` helpers in its four suspend/Flow emitter templates ([ADR-128](docs/adr/128-launch-for-csharp-runtime-helper.md)). What remains is the C# twin of the runtime as a NuGet package, blocked on the compiled-assembly packaging decision.

- [ ] The C# twin: `Interop.cs`'s roughly 1.8k fixed lines as a runtime NuGet package. Blocked on a per-library `DllImportResolver` (every `DllImport` names its library at compile time and one .NET process can host several Kotlin libraries); decide together with the opt-in compiled-assembly packaging mode under Future Improvements. The block holds for an assembly containing P/Invokes only, so [ADR-178](docs/adr/178-multi-package-coexistence.md)'s contract assembly (exception family and `KotlinOptional<T>`, no P/Invoke) is not blocked by it.

## Future Improvements

- KSP incremental processing if build times become a concern on large libraries. Prerequisite: restore a correct per-file dependency set first; the processor deliberately declares `Dependencies.ALL_FILES` to close a dropped-suspend-functions bug (full context in the [archive](docs/archive/roadmap.md))
- Map data classes to C# `record class` if a safe `with`-expression pattern can be found (see [ADR-008](docs/adr/008-data-class-mapping.md))
- Custom type mappers for arbitrary third-party dependency types the plugin will never hardcode (escape hatch). Known stdlib types such as `kotlin.time.Instant` are Phase 4 first-class mappings instead, not this item
- Pure-JVM ECMA-335 metadata reader + NuGet v3 client, dropping the .NET SDK prerequisite from the Kotlin-side build (synthesis D1) – no plugin in this space runs prerequisite-free; a genuine ergonomic edge
- Hand-written C# shim escape hatch for API members outside the auto-bridgeable subset (spm4Kmp's bridge-folder model, synthesis D2)
- Local-feed dev loop: let a C# consumer iterate against a locally built `.nupkg` before publishing (KMMBridge-style dual flow, synthesis D6). The open part is cache-safe re-publishes of a changed `.nupkg`; see the [archive](docs/archive/roadmap.md)
- Publish the Maven artifacts to GitHub Packages as a secondary registry, mirroring KStore. Tried and shelved in [#484](https://github.com/xxfast/kotlin-native-nuget/pull/484): it works, but 38 publications took 43 minutes, and GitHub Packages needs a token even to read public packages. The shared NuGet contract is mirrored there ([archive](docs/archive/roadmap.md))
- Forward un-skip/remap escape hatch: a Xamarin-`Metadata.xml`-style (or `@HiddenFromObjC`-style opt-out) mechanism to force-bind or remap a construct [ADR-064](docs/adr/064-forward-unsupported-declaration-diagnostics.md) would otherwise skip. Deferred by ADR-064's Scope; today the diagnostic's hint text names the hand-written-adapter workaround instead, the same choice ADR-043 made for reverse
- A `dogfood/` build that compiles and runs the generated reverse bindings for real published NuGet packages end to end (not just the controlled `TestDependency` fixture): the reverse diagnostics census over nine real packages shipped (`nuget-plugin/src/test/resources/dogfood/SUMMARY.md`, `scripts/verify-dogfood.sh`, a non-required `dogfood` CI job), proving the ADR-043 skip diagnostics and partial-binding behaviour on messy real-world surfaces (mixed bridgeable/unbridgeable members, legacy nullability, multi-TFM), but it only checks that generation does not throw, not that the output compiles or runs. That remaining layer's design is in [`docs/backlog/reverse-dogfooding-layer2-layer3-design.md`](docs/backlog/reverse-dogfooding-layer2-layer3-design.md)
- Opt-in compiled-assembly packaging mode: ship the C# shim as a prebuilt `lib/<tfm>/*.dll` instead of the [ADR-050](docs/adr/050-end-to-end-packaging-integration.md) source shim. Flagged by an external integration report (2026-08-20); needs its own ADR, and cuts against the no-.NET-SDK goal ([archive](docs/archive/roadmap.md))
- Expose Kotlin `Job` as a mapped C# type so cancellation can be tied to the job directly (e.g., `job.Cancel()`) instead of requiring a pre-created `CancellationTokenSource`
- NativeAOT compatibility for the generated bindings ([ADR-038](docs/adr/038-aot-compilation.md)). Reflection-free generic dispatch shipped via [ADR-094](docs/adr/094-reflection-free-generic-dispatch.md); the AOT smoke-test lane and the `[UnmanagedCallersOnly]` callback port are real roadmap items now, leaving only the interop-dialect switch below ([archive](docs/archive/roadmap.md))
- `[DllImport]` → `[LibraryImport]` for the AOT-friendly interop dialect (ADR-038 step 3, still open; narrowed by ADR-094 to the one remaining axis of the originally proposed `CSharpProfile`, since the `genericDispatch` axis no longer needs a profile toggle)
- Swap the forward *reader* from KSP to a K2/IR compiler plugin, **if and when the compiler plugin API stabilizes**. Reader only; the Gradle plugin's orchestration stays regardless. Full cost/benefit writeup in the [archive](docs/archive/roadmap.md). Weigh it against the Kotlin Toolchain item below first: the toolchain lists KSP processors first-class and configures compiler plugins by raw ID
- A Kotlin Toolchain plugin, so a standalone (non-Gradle) toolchain project can pack and publish a NuGet. Post-1.0. JetBrains recommends the toolchain for most new KMP projects as of 0.13 (2026-10), and a toolchain project cannot apply Gradle plugins; the KSP processor would run there but nothing would pack its output. Blocked on toolchain plugin publication, which the toolchain does not support yet; then a `sharedLib` hook and KSP on native targets. All inferred from the toolchain docs, nothing spiked. Details and what to keep thin in the Gradle plugin meanwhile in [`docs/backlog/kotlin-toolchain-plugin.md`](docs/backlog/kotlin-toolchain-plugin.md)
