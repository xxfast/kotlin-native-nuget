TITLE: Carry a nullable collection element on every flow and settle enum flow properties (ADR-230)

A `MutableStateFlow<List<T>?>`, `MutableSharedFlow<Set<T>?>` or `Flow<List<T>?>` element was a named skip on every owner (`SKIPPED_UNSUPPORTED_PROPERTY`, "a Flow or StateFlow element can be a List/Set/Map, but not the generic type List<Int>?"), so none of them existed in C#. An awaited `suspend fun (): MutableStateFlow<T?>` came back read-only. Flow properties on an enum were generated but nothing stood behind them. Now a nullable collection element binds settable on a class, an `object`, the top level, a held return and an awaited return, and every flow kind on an enum entry is proven end to end.

```kotlin
class SockDrawer {
  val socks: MutableStateFlow<List<Int>?> = MutableStateFlow(null)
  val tallies: Flow<Map<String, Int>?> = flowOf(null, mapOf("Oreo" to 3))
  suspend fun awaitSocks(): MutableStateFlow<List<Int>?> = socks
  fun sockTotal(): Int = socks.value?.sum() ?: -1
}

enum class Tail(val swishes: MutableStateFlow<Int>) {
  OREO(MutableStateFlow(1)) {
    override val mood: Flow<String> get() = flowOf("Oreo flicks")
  },
  MYLO(MutableStateFlow(2)) {
    override val mood: Flow<String> get() = flowOf("Mylo thumps", "Mylo thumps again")
  };

  val height: MutableStateFlow<Int> = MutableStateFlow(ordinal * 10)
}
```

```csharp
var drawer = new SockDrawer();
using KotlinMutableStateFlow<IReadOnlyList<int>?> socks = drawer.Socks;

Assert.Null(socks.Value);
socks.Value = [3, 4];
Assert.Equal(7, drawer.SockTotal());
socks.Value = null;
Assert.Equal(-1, drawer.SockTotal()); // null, not an empty pile

using KotlinMutableStateFlow<IReadOnlyList<int>?> awaited = await drawer.AwaitSocksAsync();
awaited.Value = null; // settable now

using KotlinMutableStateFlow<int> oreo = Tail.Oreo.Height;
using KotlinMutableStateFlow<int> mylo = Tail.Mylo.Height;
int myloBefore = mylo.Value;
oreo.Value = 42;
Assert.Equal(42, Tails.TailHeight(Tail.Oreo));
Assert.Equal(myloBefore, mylo.Value); // a write through Oreo leaves Mylo alone
```

Null crosses as a null handle, the way a nullable `ByteArray` already did: nothing is minted or released for it, and C# reads `IntPtr.Zero` as `null` on a `Value` read, a `ReplayCache` read and an emission, so both sides tell `null` from an empty collection. A projected component (`List<Posture>?`) stays projected behind the null guard. The refusal was `legacyFlowElementShape` never unwrapping `Nullable` over a collection; `ForwardLegacyFlowElementShape.Marshalled` carries a `nullable` flag now. The `awaitsSettableMutableStateFlow` gate is gone, so an awaited `MutableStateFlow<T?>` reuses the held route's flow-keyed write and `CompareAndSet` exports for every element kind. A `StateFlow<List<Enum>>?` member skipped the collection projection (`stateFlowNullableBox`) and now projects it. The two diagnostic hints that said "non-nullable" now say "List/Set/Map, nullable or not".

Enum flow properties were already extension properties on `TailExtensions`, the entry crossing as its ordinal; this adds the proof for a body `val`, a constructor `val` and an `abstract val` overridden per entry, plain and hot, read-only and held. Each entry keeps its own storage. A `var` flow setter on an enum stays a named skip; ADR-233 binds it in its own PR. The flaky `SealedArmCallbackPairTests` row is serialized by `JobIdleWatchersCollection` and re-ran 20 times clean.
