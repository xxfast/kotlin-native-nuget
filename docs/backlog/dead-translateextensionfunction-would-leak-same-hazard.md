# Dead code `CirTranslator.translateExtensionFunction` would leak the same `Native_@`-escaped extern name if it were ever revived.

**`CirTranslator.translateExtensionFunction`** (`nuget-processor/src/main/kotlin/io/github/xxfast/kotlin/native/nuget/processor/cir/CirTranslator.kt:792`, with its two `CirMethod` constructions at `:978` and `:988`) **has zero callers anywhere in `main` or `test`** (verified: `grep -rn "translateExtensionFunction(" nuget-processor/src/main/kotlin nuget-processor/src/test/kotlin` returns only its own declaration).

It builds the C# member name in the reverse order every live producer uses: `toCSharpName(toCName(funcName)).replaceFirstChar { it.uppercase() }` (`:801-802`), `toCSharpName` *before* PascalCasing rather than after. It then mints its own extern name directly, `"Native_$csName"` (`:978` for the `[DllImport]`, `:988` for the wrapper's `nativeName`), instead of going through `CirMethod.resolvedExternName` (added by ADR-090's 2026-09-10 amendment). If it were ever wired up again for `fun Foo.lock()`, uppercasing `@lock` leaves `@lock` (`CSHARP_RESERVED` is all-lowercase, so the escape survives PascalCasing done second), and the extern would render as `Native_@lock`, invalid C#, outside the fail-fast rule the amendment added: that rule only guards the two call sites `resolvedExternName` folded together, and this dead function never reads it.

It went unnoticed because nothing calls it. `ForwardCirPlanProjection.extension` (`:405-475`) is the live route for extension functions; no test builds a `KSFunctionDeclaration` fixture that reaches `translateExtensionFunction` either.

Discovered alongside [ADR-090](docs/adr/090-ordinary-class-method-overloads.md)'s 2026-09-10 amendment, while enumerating every producer of a `CirMethod` with a null `externName` to confirm none could reach the fallback in practice. Recommend deleting `translateExtensionFunction` rather than aligning it: it is unreachable, and the alignment would be dead work.
