# A `kotlin.sequences.Sequence<T>` parameter or property vanishes from C# with no diagnostic

**A function parameter or property typed `kotlin.sequences.Sequence<T>` disappears from the generated C# entirely, on every route, with no `SKIPPED_*` diagnostic.** `ForwardBridgeTypeClassifier.kt` (~lines 204-206) has no stdlib-known branch for `Sequence`: it is a plain `INTERFACE` with a type parameter, so it falls into the generic-interface arm and comes out as `BridgeType.SpecializedProtocol("generic declaration kotlin.sequences.Sequence")`, the exact same shape a user's own generic interface would produce. `ForwardCallablePlanner.kt` (~line 2456) then maps any `SpecializedProtocol` name starting with `"generic declaration "` to `ForwardPlanSkipReason.GENERIC`, a `droppedFromCSharp = false` deferral that hands the callable to the generic legacy route instead of `NugetProcessor.kt`'s `droppedCallables` warning path. The generic legacy route only knows how to re-emit a genuine user-generic-class member, so a `Sequence`-typed callable is silently absent from `Interop.cs`: no export, no warning, nothing.

Root cause: `ForwardBridgeTypeClassifier.kt:~204-206` (the generic-interface fallback) and `ForwardCallablePlanner.kt:~2456` (the `GENERIC` skip-reason mapping), the same silent-handoff shape as the sealed and interface "silently dropped, no diagnostic" items already on this roadmap.

Why it went unnoticed: nothing in the existing fixture set exercises a `Sequence`-typed member expecting it to bind. The opposite is true, `Tier1DroppedExtensionEmissionTest`'s fixture (`val Patient.tags: Sequence<String> get() = sequenceOf(name)`) *relies on* the silent drop to prove an unrelated extension-emission fix, so the test suite is green precisely because it assumes the current silence is correct.

Fix shape: recognise `kotlin.sequences.Sequence` by qualified name in the classifier's known-stdlib block (alongside `Instant`/`Duration`/`Uuid`) and return a named `Unsupported` instead of falling through to the generic-interface arm, so the existing `SKIPPED_UNSUPPORTED_INPUT`/`SKIPPED_UNSUPPORTED_RETURN`/`SKIPPED_UNSUPPORTED_PROPERTY` machinery names it like any other unbridgeable type, rather than a bare silent skip.

Verified by a `packNuget` probe during this item: both a class member and a top-level function typed with `Sequence<T>` vanish from the generated C# with no diagnostic in either case. Discovered alongside [ADR-064](docs/adr/064-forward-unsupported-declaration-diagnostics.md)'s husk-elision amendment, while confirming the empty-static-class fix does not also mask this callable's disappearance.
