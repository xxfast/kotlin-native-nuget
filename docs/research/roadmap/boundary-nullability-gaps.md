### A. Null lambda arguments

A0. **Which route the item means (verified by reading).** The backlog file names `nuget_func1_invoke` and friends. Those exports moved: `exports/GenericClassExports.kt` no longer exists at `651cb7d0` (which change removed it was not traced); they now live in the shipped runtime artifact, `nuget-runtime/src/nativeMain/kotlin/io/github/xxfast/kotlin/native/nuget/runtime/NugetRuntime.kt:306-346` (`func0..3`) and `:349-` (`suspend_func0..3`). They serve the RETURNED lambda route: Kotlin hands C# a lambda, C# calls `KotlinFunc<...>.Invoke(...)` or `KotlinAction<...>.Invoke(...)` (`cir/CirFunctionRenderer.kt:59-189`, suspend twins `:231-` onward). So the item is "a C# caller passes null INTO a Kotlin lambda". The task's two other readings (a nullable lambda parameter type, and Kotlin passing null into a C# callback) are a different route (ADR-036/102 per-call, ADR-037 stored) and are covered as A2.

A0b. **The route binds only at a top-level function return (verified by spike; CONTRADICTS pass 1's sample fixture).** A Tier 1 cell with `class Greeter { fun recorder(): (String?) -> Unit ... }` produced, for each of the three members: `[nuget:SKIPPED_UNSUPPORTED_RETURN] Skipping spike.a1.Greeter.recorder: a lambda binds at a class-method parameter and a top-level function return, but not at this position. take the lambda as a parameter of an ordinary class method (a per-call one, or an add/remove pair), or return it from a top-level function`. The same three lambdas as top-level functions bound. The mirror holds on the input side: a top-level `fun eachInt(cb: (Int?) -> Unit)` is `SKIPPED_UNSUPPORTED_INPUT` with the same sentence, so the per-call route exists only on class methods.

A1a. **The C# type hides the nullability (verified by spike).** Tier 1 cell, top-level `fun recorder(): (String?) -> Unit`, `fun describer(): (Int?) -> String`, `fun finder(): (String) -> String?`, `fun plain(): (String) -> Unit` rendered `public static KotlinAction<string> Recorder()`, `public static KotlinFunc<int, string> Describer()`, `public static KotlinFunc<string, string> Finder()`, `public static KotlinAction<string> Plain()`: the nullable and non-null spellings are identical, no diagnostic, generated Kotlin compiles clean. Mechanism, verified by reading: `csTypeArgument` (`cir/CirTypeMapping.kt:440-460`) resolves through `expandAliases()` and never reads `isMarkedNullable`; no caller re-adds `?` (`csTypeArgumentNames` `:478-490`, `csLambdaType` `:513-518`). `(String?) -> Unit` spells `KotlinAction<string>`, `(Int?) -> Unit` spells `KotlinAction<int>` (null is not even expressible), `() -> String?` spells `KotlinFunc<string>`. This is the consumer visible half of the defect and the backlog file does not mention it.

A1b. **What null does today, per `T` (verified by reading; runtime outcomes inferred).** `WrapArg<T>` (`CirFunctionRenderer.kt:41-52`, suspend copy `:231-242`):
- `T = string`, `null` passed: `:43` calls `wrap_string((string)null)`. Kotlin `export_nuget_wrap_string(value: String)` (`NugetRuntime.kt:246-248`) receives a null C string for a non-null `String` parameter. Pass 1 inferred undefined behaviour inside the K/N string conversion; the spike below corrects that to an uncaught Kotlin `NullPointerException` that terminates the host (exit code 3), still before `nuget_func1_invoke` is reached.
- `T = int?`: `typeof(int?) != typeof(int)`, every branch misses, `:51` throws `NotSupportedException`. Same for `T = Cat` with `null` (`:50` `is INugetHandle` is false for null).
- Only a hypothetical `IntPtr.Zero` argument would reach `NugetRuntime.kt:316` (`arg0.asStableRef<Any>().get()` on a non-nullable `COpaquePointer`), which is the line the backlog names. So the backlog's crash site is real but unreachable today; the reachable failures are the three above.
- Null RETURN: `NugetHandles.retain(fn.invoke(param0) as Any)` (`NugetRuntime.kt:309`, `:317`, `:330`, `:345`). Verified by spike at the mirror (below): `null as Any` throws `NullPointerException` inside a `@CName` export with no error slot (the signature has no `errorOut`), which terminates the host. The suspend twins already tolerate a null result only for `Unit` (`:360`, `:378`).
- **Runtime outcomes, verified by spike at a scratch MIRROR, not at the shipped artifact.** A scratch K/N 2.4.10 DLL with exports whose bodies copy `NugetRuntime.kt:246-248` and `:313-318` verbatim (`StableRef.create(...).asCPointer()` standing in for `NugetHandles.retain`), called from C# with the generated import's exact shape (`private static extern IntPtr wrap_string(string value)`, Cdecl, default marshalling). Header: `extern void* p_wrap_string(const char* value);`. Observed:
  - `wrap_string(null!)`: `Uncaught Kotlin exception: kotlin.NullPointerException` at `ThrowNullPointerException` / `kfun:kotlinx.cinterop#createStablePointer(kotlin.Any)` / `kfun:#pWrapString(kotlin.String)` / `p_wrap_string`; the host process dies with exit code 3. So it is not undefined behaviour and not an empty string: the null C string arrives as a null reference inside a non-null `String`, and the first non-null use throws an NPE that nothing catches. A C# `try/catch` cannot see it.
  - `invoke(recorder, IntPtr.Zero)`: same uncaught NPE, at `kfun:kotlinx.cinterop.StableRef#get()` inside the invoke export. Process dies.
  - `invoke(finder, wrap("Mylo"))` where the lambda returns null: uncaught NPE inside the invoke export (the `as Any`), exit code 3.
  - The recommended shape (`arg0: COpaquePointer?`, `arg0?.asStableRef<Any>()?.get()`, `fn.invoke(param0)?.let { retain(it) }`, return `COpaquePointer?`) on the same DLL: `fixed recorder(Zero) returned 0x7FFE1EAC6E41 (Unit box), lastSeenIsNull=True`, `fixed finder('Mylo') returned 0x0`, `fixed finder('Oreo') nonzero=True len=4`. Note the `Unit` lambda returns a non-zero box, which is what `KotlinAction.Invoke`'s existing `result != IntPtr.Zero` guard disposes.
  - Still inferred: that the shipped `NugetHandles.retain` behaves like `StableRef.create` here (it is `retain(value: Any)`, so the NPE would fire at the same cast), and the `int?` / `Cat` `NotSupportedException` paths, which are plain C# and were not run.

A1c. **The fix pieces already exist (verified by reading).** `NugetMarshal.Wrap<T>(T value, out bool owned)` (`CirMarshalRenderer.kt:306-339`) returns `IntPtr.Zero` for null (`:312`), normalises `Nullable<T>` to its underlying (`:313`), covers the six narrow kinds and `char` (ADR-098), and reports ownership. `NugetMarshal.FromHandle<T>` returns `default!` for `IntPtr.Zero` (`:131`) and dispatches `Nullable<T>` on the underlying (`:138-`). `WrapArg<T>` is a strictly worse private copy of `Wrap<T>`. `Wrap<T>` (`:306`) and the `nuget_wrap_*` imports (`:83-104`) sit BEFORE the first `if (helper.includes...)` gate in `renderMarshalHelper` (first gate `:343`), so they are emitted in every file that has a `NugetMarshal`, and the func helper already depends on `NugetMarshal.FromHandle` (`CirFunctionRenderer.kt:78`), so no CS0103 and no hoisting is needed.

A1d. **Related leak (verified by reading, not measured).** `Invoke` never disposes `boxedArg$i` (`CirFunctionRenderer.kt:106-110`, `:171-175`) and `nuget_funcN_invoke` only `get()`s them, so every scalar or string argument leaks one `StableRef` per call. No `LeakTests` row mentions `KotlinFunc` or `KotlinAction` (grep, 2026-09-21). Delegating to `Wrap<T>` and disposing on `owned` closes it in the same edit.

B7. **Prior art (inferred, general knowledge, not re-fetched).** No mainstream interop tool invents a nullable-key dictionary: Swift `Dictionary` requires a `Hashable` non-optional in practice for ObjC bridging (`NSDictionary` rejects nil keys), Java `Map.of` and `ConcurrentHashMap` reject null keys, and .NET's own `Dictionary`, `ImmutableDictionary` and `FrozenDictionary` all throw. A Kotlin `Map<String?, V>` is the outlier, so declining it is the idiomatic answer on the C# side.

### C. Bare `Char?`

C1. **The premise of ROADMAP line 56 is already dissolved (verified by reading).** ADR-098 established that `KChar` is `unsigned short` and ships `[MarshalAs(UnmanagedType.U2)]` on every by-value `char` slot (`cir/CirClassRenderer.kt:490-511`, `charParameterMarshal` and `charReturnMarshal`; `CirMarshalRenderer.kt:47`, `:104`). The backlog file's own 2026-08 correction says the same. What is left is only the fan-out arms.

C2. **The property crash is real (verified by spike).** Three Tier 1 cells, `class Tag(var initial: Char?)`, `class Tag { val initial: Char? = null }` and a top-level `val topInitial: Char? = null`, each threw out of `KotlinSymbolProcessing.execute`: `java.lang.IllegalStateException: Forward property direct nullable getter is invalid for spike.cpv.Tag.initial: Char` at `ForwardPropertyKotlinEmitterKt.addGetter(ForwardPropertyKotlinEmitter.kt:141)` via `addForwardPropertyPlanExports(:16)`, `ClassExportsKt.addClassExports(ClassExports.kt:115)` (top-level: `PropertyExportsKt.addPropertyExports(PropertyExports.kt:23)`), `NugetProcessor.generateCNameWrappers`, `NugetProcessor.process(NugetProcessor.kt:1571)`. (three output lines per `which` joined here for width; the last line is the by-value pair: `[return: MarshalAs(U2)] char Echo([MarshalAs(U2)] char)` and `int In([MarshalAs(U1)] bool has, [MarshalAs(U2)] char c)` against `fun probeCharIn(hasValue: Boolean, c: Char): Int`.) ## Recommendation

### A. Fix, two PRs

**A1 (returned-lambda route, the item as written; size S/M).** End state: the erased lambda boundary is null tolerant in both directions and honest in its spelling.
1. Spell: `csTypeArgument` appends `?` when `type.isMarkedNullable || resolved.isMarkedNullable` (the same two-sided read `ForwardBridgeTypeClassifier.classify` uses at `:73-79`). `KotlinAction<string?>`, `KotlinFunc<int?>`.
2. Write: delete `WrapArg<T>` and its six private `wrap_*` imports; `Invoke` and `InvokeAsync` call `NugetMarshal.Wrap<T>(arg, out bool owned)` and dispose on `owned` in a `finally`. This also closes the ROADMAP `WrapArg<T>` item's narrow-scalar and `char` half (line 66) and the A1d leak, and is step 2 of `docs/research/roadmap/generic-route-fromhandle-interface-identity.md` for free (that memo wants the same call sites to reach `HandleOf`; sequence with its owner).
3. Runtime: `nuget_funcN_invoke` and `nuget_suspend_funcN_invoke` take `COpaquePointer?` arguments (`arg0?.asStableRef<Any>()?.get()`) and return `COpaquePointer?` (`fn.invoke(...)?.let(NugetHandles::retain)`). C ABI unchanged (a pointer is a pointer); `ForwardAbiContract.kt:523-552` rows unchanged (inferred). `KotlinAction.Invoke` already guards `result != IntPtr.Zero` (`CirFunctionRenderer.kt:142`, `:175`); `FromHandle<TResult>` already returns `default!` on zero. Ordering constraint for step 2: the suspend exports read `param0` synchronously (`NugetRuntime.kt:373`) BEFORE `launchForCSharp` (`:376`), which is the only reason disposing the box right after the native call returns is safe. An implementer who moves that `get()` inside the launch block creates a use-after-free; pin it with a comment.

**A2 (per-call and stored callback routes; size S).** Named skip now: `hasLegacyLambdaParameter` and the CIR twin refuse a lambda whose own type is nullable or any of whose argument or return types is nullable, with a `SKIPPED_UNSUPPORTED_INPUT` that names the argument (the `legacyRefusedParameter` shape, `exports/ClassExports.kt:175`). The full route (`IntPtr.Zero` thunk pointer means Kotlin `null` with an `Action<int>?` spelling; nullable payloads riding the null pointer on the handle path and a has-value pair on the by-value path) is deferred scope: it touches ADR-102's thunk table and has no consumer asking.

*Note 2026-09-21 (spikes), correcting A2:* the refusal set is, per route, exactly what the cells showed. Per-call: `(Int?) -> Unit` and `(Cat?) -> Unit` (build abort today), `(String?) -> Unit` and `(Int) -> String?` (compile, NPE on a real null; the return shape is new to this memo). Stored: every nullable payload, `String?` included (build abort today). For these the skip only ever replaces a broken build or an uncatchable crash, so no CHANGELOG removal line is owed for the abort shapes. The nullable lambda TYPE needs the opposite edit: it already binds AND already reports a skip, so the implementer must pick one. Recommendation: make the skip true (the legacy selector consults the planner's `NULLABLE` verdict and stops binding it), because the binding it produces can never deliver `cb == null` to the Kotlin body, which is the only reason an author writes `((Int) -> Unit)?`. That IS a visible removal of a member that compiles today; it goes to open question 3. The first red cell for A2 is `Tier1NamedSkipDiagnosticsTest`: assert that a declaration reported `SKIPPED_*` has no member in `Interop.cs`, which fails today on this shape.

Alternatives rejected:
- Patch only `NugetRuntime.kt:316` as the backlog suggests: the null never gets there (A1b); fixes nothing observable.
- Add a `value == null` first line to `WrapArg<T>` and keep the copy: leaves the narrow-scalar gap and the leak, and a third boxing switch to keep in sync.
- Named skip for A1 too (refuse any lambda with a nullable type argument): removes a member that binds fine for non-null calls today; a regression for anyone using `(String?) -> Unit` with non-null values.

Add `internal fun BridgeType.Collection.declinesNullableMapKey(): Boolean = (kind is MAP or MUTABLE_MAP) && key is BridgeType.Nullable` beside `declinesByteArrayComponent` (`ForwardCallablePlanner.kt:3812-3820`), and consult it in the four places that function is consulted: `isBridgeableComponent`'s collection arm (`:3752`), `skipReason()`'s collection arm (`:4165-4171`, so the skip is attributed to the key, not to whichever slot is first), the property planner's `isReadable` (`ForwardPropertyPlanner.kt:960-970`) and `isWrappableComponent` (`:3886`, replacing the inline test).     Assert.Equal('O', TagKt.FirstLetter("Oreo"));
```csharp
    Assert.Null(TagKt.FirstLetter(""));
}
```
The non-ASCII characters are the point: an ANSI width regression passes an all-ASCII test. Verified by spike (C5): a bare `out char` returned `'A'` intact, `'é'` as U+FFFD and `'猫'` as U+002B.

## Open what-questions

1. **A: is a lambda's nullable type argument re-spelled (`KotlinAction<string>` becomes `KotlinAction<string?>`) a breaking change anyone depends on?** Recommendation: treat as a defect fix; for reference types it is annotation only (same runtime type), and for value types (`KotlinAction<int>` becomes `KotlinAction<int?>`) no existing caller could have passed null, but their declared variable types change. No fixture has the shape. Human decision: pending.
2. **A: `NugetRuntime.kt` is a published artifact. Does an export signature change from `COpaquePointer` to `COpaquePointer?` need a runtime version gate?** Recommendation: no; the C symbol and width are identical (inferred), and processor plus runtime ship in lockstep. Confirm against ADR-128/129's runtime versioning rule. *2026-09-21:* the symbol half is verified by spike at the mirror: K/N 2.4.10 emits `extern void* p_func1_invoke(void* handle, void* arg0);` for the non-null spelling and `extern void* p_func1_invoke_fixed(void* handle, void* arg0);` for the nullable one, identical C signatures. The versioning-rule half is still unread. Human decision: pending.
3. **A2: named skip or leave as is?** A skip removes members that bind today when the author declared `cb: ((Int) -> Unit)?` but C# callers always pass a delegate. Recommendation: skip only when an ARGUMENT or RETURN type inside the lambda is nullable (those cannot compile or NPE, A2b); for a nullable lambda TYPE keep binding as today and document that C# must pass a non-null delegate, adding an `ArgumentNullException.ThrowIfNull(callback)` to the wrapper. Human decision: pending. *Reframed 2026-09-21 (spikes):* the first half is no longer a judgement call: the nullable payload shapes abort the generated-Kotlin compile (per-call `Int?` and handle payloads, every stored payload) or NPE uncatchably, so skipping them removes nothing that works. The second half changed shape: a nullable lambda TYPE today binds as `Action<int>` AND is reported as skipped (warning, JSON row, XML remark). "Leave as is" is therefore not available; the question is which side yields. Option (i): stop binding it, making the existing diagnostic true; a visible removal, needs a CHANGELOG line. Option (ii): keep binding, suppress the false diagnostic, add `ThrowIfNull`; nothing is removed, but the Kotlin body still can never see `cb == null`. Main-thread recommendation: (i), see the A2 note under Recommendation; pass 1 recommended (ii) without knowing the diagnostic already fires. Human decision: pending.
4. **B: reuse `COLLECTION` with a key-specific hint, or mint `NULLABLE_MAP_KEY`?** Recommendation: reuse `COLLECTION`; the input side has shipped that wording since ADR-083 and the Tier 1 pins already assert it. A new reason is only worth it if `BYTE_ARRAY`-style hint routing cannot take a per-detail hint.
5. **B: is this a regression risk for anyone?** A `Map<String?, Int>` return stops binding. Recommendation: accept; per B4 it cannot have compiled under `NugetCompileInteropTask`, so nobody can be using it. If the B4 spike shows it DID compile, the skip is still right (a getter that throws on a real null key is the trap rejected above), but it is then a visible removal and needs a CHANGELOG line. *Resolved 2026-09-21 by spike (B4):* it does not compile, at any of seven positions, under the gate's csproj text, so no project that runs `nugetCompileInterop` can be shipping it. Residual: a project on a plugin version older than ADR-138, or with `dotnet` absent (the gate then skips with a warning), could have packed it; their consumers would hit CS8714 as a warning or error in their own build depending on their settings. Worth one CHANGELOG sentence, not a blocker.
6. **C: `out ushort` plus cast (recommended) or `[MarshalAs(U2)] out char` (ADR-069's literal mirror)?** Recommendation: `ushort`; it makes the feature independent of the one unverified claim. Human decision: pending. *Updated 2026-09-21:* both are verified correct on JIT (C5), so this is now a how-question for the implementer, not a what-question for the human. `ushort` remains the recommendation (reuses the Enum `valueOut` path, blittable under AOT without a check). Only a bare `out char` is wrong.
7. **C: one PR or property-first?** Recommendation: one PR; if the C5/C6 spike fails, ship the property and parameter arms (no OUT slot involved) and leave the two return positions named `NULLABLE`. *Resolved 2026-09-21:* the C5/C6 spike passed, so one PR, all positions.
