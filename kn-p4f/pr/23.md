TITLE: Bind a member extension declared inside every owner (ADR-238)

ADR-238 bound a member extension on a class. The same shape elsewhere didn't: an extension property declared inside any other owner, or a `suspend` or `Flow` extension function declared inside an object, companion, enum or value class, generated Kotlin that didn't compile, with no diagnostic. A library declaring one didn't build. Now every owner binds them, with the receiver always an argument.

```kotlin
object Napkin {
  val Loafer.snooze: String get() = "$name snoozes on the napkin"

  suspend fun Loafer.curlUp(minutes: Int): String {
    delay(1.milliseconds)
    return "$name curls up on the napkin for $minutes"
  }
}

enum class Drowse {
  CATNAP,
  DEEP;

  val Loafer.snooze: String get() = "$name ${name.lowercase()}s on ${this@Drowse.name}"

  fun Loafer.purrs(count: Int): Flow<Int> = flowOf(ordinal, count)
}

value class Paws(val count: Int) {
  fun Loafer.kneads(times: Int): Flow<Int> = flowOf(count * times)
}

interface Chorus {
  val String.shout: String

  fun String.echo(times: Int): String
}
```

```csharp
using var mylo = new Loafer("Mylo");
Napkin.GetSnooze(mylo);                       // "Mylo snoozes on the napkin"
Napkin.SetDozeCount(mylo, 4);
Napkin.GetDozeCount(mylo);                    // 4
await Napkin.CurlUpAsync(mylo, 5);            // "Mylo curls up on the napkin for 5"

Drowse.Deep.GetSnooze(mylo);                  // "Mylo mylos on DEEP"
using KotlinFlow<int> purrs = Drowse.Deep.Purrs(mylo, 7);
await Drain(purrs);                           // [1, 7]

var paws = new Paws(4);
using KotlinFlow<int> kneads = paws.Kneads(mylo, 3);
await Drain(kneads);                          // [12]

private sealed class CSharpChorus : IChorus
{
    public string GetShout(string receiver) => receiver + "!";
    public string Echo(string receiver, int times) => string.Concat(Enumerable.Repeat(receiver, times));
    public void Dispose() { }
}
Bindles.Sing(new CSharpChorus(), "purr");     // "purr!|purrpurr"
```

A member extension property becomes an accessor pair, `GetX(receiver)` and `SetX(receiver, value)`, the way Kotlin/JVM lowers it; a `Flow` typed one is a flow method (`Napkin.Snores(mylo)`). On the `suspend` and `Flow` routes the receiver rides as an extra leading parameter beside the owner's own slot. On the enum and value class routes that slot is already named `receiver`, so the extension receiver is `receiver_` (C# rejects two parameters with the same name, CS0100); calls are positional, so only IntelliSense sees it.

On an interface the accessors and functions land on `I<Name>`. A Kotlin implementer works, and so does a C# one when the receiver is a type the bridge carries at a slot (`string` above). A C# implementation whose member extension extends a class keeps `SKIPPED_UNIMPLEMENTABLE_INTERFACE` until ADR-233's amendment widens the slot types.
