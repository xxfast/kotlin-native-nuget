# Forward `BuildMapped`, the ADR-029 .NET-exception-to-Kotlin-exception type map, is `private`, so the reverse direction cannot call it and has to duplicate…

> Extracted verbatim from `ROADMAP.md` (Tooling & Test Integrity) in the 2026-08-31 roadmap slim-down.

**Forward `BuildMapped`, the ADR-029 .NET-exception-to-Kotlin-exception type map, is `private`, so the reverse direction cannot call it and has to duplicate the same switch instead.** `CirErrorRenderer.kt:59` renders `private static Exception BuildMapped(...)`. [ADR-087](docs/adr/087-kotlin-slot-exceptions.md) stage 2 needed the identical mapping to build a `KotlinException` from a Kotlin-implemented interface member's error envelope, and rather than change forward-generated output every existing consumer already compiles against, it emits its own `NugetKotlinErrors.Map` in `NugetRuntimeRegistration.cs` with the same nine cases, commented "Mirrors the forward `BuildMapped` switch. Duplicated, not shared ... If the forward table gains a row, add it here too." Cheap fix, one-line-ish in `nuget-processor`: render the generated factory as `public`/`internal` instead of `private` so the reverse-generated shim can call it directly, retiring the duplicate switch. Tooling or Phase 11 adjunct. Discovered alongside [ADR-087](docs/adr/087-kotlin-slot-exceptions.md).
