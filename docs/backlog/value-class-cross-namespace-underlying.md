# A value class whose underlying enum/class lives in a different namespace emits a bare member type in its `readonly record struct`

> Extracted verbatim from `ROADMAP.md` (Phase 2).

**A value class whose underlying type is an enum or class in a different namespace emits a bare member type inside its generated `readonly record struct` (CS0246).** `CirClassTranslator.kt:1617` takes `underlyingResolved.declaration.simpleName.asString()` and `:1738` passes it through unqualified to the struct member; `cir/CirObjectRenderer.kt:23` and `:62` render it bare, while the same struct's constructor body already qualifies the cast (`(global::Interop.Mood)`). Symptom: with a cross-namespace enum/class underlying, the generated struct declares a bare-named member (e.g. `public Mood Mood { get; }`) that fails `CS0246` once the underlying's namespace differs from the value class's own, the same shape #41 fixed at the object-handle/enum/interface render sites above, but this render site was never routed through the fix. Went unnoticed because every value class in `test-library` has a same-namespace underlying; `Tier1ValueClassEnumUnderlyingTest.kt` asserts the bare `public Mood Mood { get; }` shape today, so the gap is pinned by an existing test rather than merely absent coverage. Verified by source reading and that test; not runtime-reproduced, since no fixture pairs a value class with a cross-namespace underlying. Discovered alongside the fix for [#41](https://github.com/xxfast/kotlin-native-nuget/issues/41) above, same defect class, different render site.
