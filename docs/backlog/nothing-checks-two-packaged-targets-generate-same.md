# Nothing checks that two packaged targets generate the same C# API, and after [ADR-074](docs/adr/074-expect-actual-declarations.md) they can legitimately differ.

> Extracted verbatim from `ROADMAP.md` (Tooling & Test Integrity) in the 2026-08-31 roadmap slim-down.

**Nothing checks that two packaged targets generate the same C# API, and after [ADR-074](docs/adr/074-expect-actual-declarations.md) they can legitimately differ.** `packNuget` packages exactly one target's `Interop.cs` ("Pick the first available target's output", `NugetPlugin.kt:331-339`; **Verified**, read in source) while shipping *every* target's binary, so the single packaged C# API is the contract every platform's `.dylib`/`.dll` must satisfy. That was harmless while the export set was target-independent. ADR-074 makes the `actual` the forward export root, and an `actual` may legally declare public members its `expect` never mentioned, so two targets can now produce genuinely different C# APIs and only one of them ships. A member present in the packaged target's `actual` but absent from another's generates a `[DllImport]` that resolves to a missing entry point on that platform: a runtime `EntryPointNotFoundException`, not a build error. Neither existing guard can catch it, and for structural reasons rather than by omission: `ForwardAbiContract` ([ADR-055](docs/adr/055-forward-abi-contract-check.md)) compares the C# and Kotlin halves generated in the **same** run, and each target's run is internally consistent; a single KSP run cannot see it either, because the other target's source set is not in the compilation (**Verified** by spike, `getAllFiles()` for `kspKotlinMacosArm64` lists only `commonMain`, `nativeMain` and `macosArm64Main`). Fix is a plugin-level check, not a processor one: run KSP for every packaged target and diff the ADR-055 forward ABI contract manifests, failing generation when they disagree. Note this is not exclusively an `expect`/`actual` concern; ADR-074 is what makes it reachable through ordinary, correct Kotlin rather than only through a hand-written per-target source set. ADR-074's Decision 3 (a top-level `actual` takes its C# static class name from the `expect`'s file) removes the most likely *accidental* instance, the per-target file name, but not the general case. Split out of [ADR-074](docs/adr/074-expect-actual-declarations.md) with the human, deliberately out of that feature's scope.
