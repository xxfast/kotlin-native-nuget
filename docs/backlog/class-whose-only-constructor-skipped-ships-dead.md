# A class whose only constructor is skipped ships as a dead public type: it appears in `Interop.cs` with an `internal Foo(IntPtr handle)` and no public…

> Extracted verbatim from `ROADMAP.md` (Phase 3: Basic type support) in the 2026-08-31 roadmap slim-down.

**A class whose only constructor is skipped ships as a dead public type: it appears in `Interop.cs` with an `internal Foo(IntPtr handle)` and no public constructor, so a consumer can see the type and has no way to build one.** Any of its instance members that did bind are equally unreachable, because nothing can produce an instance. The only signal is the `SKIPPED_*` diagnostic on the constructor in the *Kotlin* build log; the generated C# says nothing, and the type still compiles, so a consumer hits it as "why can't I `new` this?" with no explanation at the C# surface. Pre-existing and general (any constructor skip reason gets there: an unsupported parameter type, a `Map`/`Set` component the write side cannot box, and so on), not specific to any one feature. Same family as the empty-static-class-stub item above, and cosmetic in the same sense (it compiles, and carries no `DllImport` the consumer can misuse), but worse in effect, since a stub class advertises nothing while a dead type advertises an API that cannot be reached. Two candidate fixes, not decided: drop the class from the generated C# entirely when it has no public constructor and no static members, or keep it and emit a class-level diagnostic naming the skipped constructor. Discovered alongside [ADR-077](docs/adr/077-value-classes-at-ordinary-positions.md) sub-item 1, whose `Admission(chart: ChartId, ward: String)` fixture was in exactly this state before the feature landed (its single constructor skipped with `VALUE_CLASS`), which is what made the shape visible.
