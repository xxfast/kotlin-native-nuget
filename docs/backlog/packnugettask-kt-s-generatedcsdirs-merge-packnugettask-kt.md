# `PackNugetTask.kt`'s `generatedCsDirs` merge (`PackNugetTask.kt:80-81`) silently drops a missing directory with `?: emptyList()`, the same silent-skip shape…

> Extracted verbatim from `ROADMAP.md` (Tooling & Test Integrity) in the 2026-08-31 roadmap slim-down.

**`PackNugetTask.kt`'s `generatedCsDirs` merge (`PackNugetTask.kt:80-81`) silently drops a missing directory with `?: emptyList()`, the same silent-skip shape ADR-093 just retired for `nativeLibDirs`, but left standing for the generated-C# side.** `dir.listFiles()?.filter { it.extension == "cs" } ?: emptyList()` treats a `generatedCsDirs` entry that does not exist (or is not a directory) the same as one that legitimately has no `.cs` files, so a producer wired up wrong (KSP output moved, a reverse shim task not run) contributes silently zero content instead of failing the pack. Unverified whether this is reachable in practice, since every current producer (`kspOutputDir`, `nugetGenerateShims.csharpOutputDir`) is a task-managed output directory that always exists by the time `packNuget` runs; nothing in the test suite exercises a genuinely missing entry. Noted while implementing ADR-093's equivalent fail-fast for `nativeLibDirs`; not fixed here, to keep that change scoped to native libraries.
