# Collection-typed slots for a Kotlin-implemented C# interface.

> Extracted verbatim from `ROADMAP.md` (Phase 13: Reverse bidirectional — implementing C# contracts in Kotlin) in the 2026-08-31 roadmap slim-down.

**Collection-typed slots for a Kotlin-implemented C# interface.** Split out of the item above at [ADR-086](docs/adr/086-object-interface-slots-kotlin-bridge.md)'s own scoping gate, on sequencing rather than difficulty: the reverse direction could not marshal a BCL collection (`List`/`Map`/`Set`) at *any* position (`List<int>` was `skipped_unbound_generic_instantiation`; no `nuget_list_*`-style reverse helpers existed), so a collection-typed slot would have had to invent the entire reverse collection vocabulary as a side effect of an interface feature.

**Update, [ADR-155](docs/adr/155-csharp-collections-in-kotlin.md):** no longer blocked. The reverse collection wire now exists (one pointer to a `[count][8-byte slot]...` buffer), and this item's own wire is that ADR's return path run inside the callback, with the allocation side flipped for a slot return (Kotlin allocates with the allocator C# frees: `malloc` on Unix, `CoTaskMemAlloc` on Windows, the expect/actual mirror of `freeManagedString`); **inferred, not verified**. Today a collection-typed interface slot member is a named skip: `skipped_kotlin_bridge` (`isKotlinBridgeSlotType`, gained a `false` arm for a collection type) or `skipped_collection_position` (`isV1Type(allowCollections = false)`), never a silent drop or broken generation.
