TITLE: Set `var` flows from C# and hand any flow back (ADR-233)

#591 gave a cold `Flow` `var` a setter, but only Tier 1 stood behind it. At runtime it threw `ArgumentException` for any `KotlinFlow` a Kotlin member returned and for any C#-made `KotlinFlow.From(...)`. Hot, sealed and generic owners got no setter at all, and a Kotlin-backed member function's hot flow couldn't be handed back through a C# implementation. Now every owner's `var` flow takes a setter, and any Kotlin flow can go back in.

```kotlin
class Hopper(var source: Flow<String>) {
  suspend fun drain(): String = source.toList().joinToString()
}

fun hopper(items: List<String>): Hopper = Hopper(flowOf(*items.toTypedArray()))
```

```csharp
using Cattery.Hopper oreos = Cattery.Catteries.Hopper(["kibble"]);
using Cattery.Hopper mylos = Cattery.Catteries.Hopper(["tuna", "salmon"]);

oreos.Source = mylos.Source;
await oreos.DrainAsync(); // "tuna, salmon"

oreos.Source = KotlinFlow<string>.From(Each("chicken", "duck"));
await oreos.DrainAsync(); // "chicken, duck"
```

A flow a member returned asks Kotlin for a fresh handle when it's handed back: a new per-member export that re-runs the function with the same arguments. Members taking a `suspend` lambda or a `Flow` parameter don't get one, and held `Mutable*` returns already own their handle. `Flow<Throwable>` elements reach Kotlin as `NugetManagedException`, message `"Type: message"`. A C# `ILitter<T>` (a suspend member returning a `Flow` of the interface's own `T`) is now accepted through `NugetTasks.BeginFlow<TFlow, T>`. A `var` flow slot registers its own `KotlinFlow<E>` factory entry; it used to rely on the module sighting one elsewhere.
