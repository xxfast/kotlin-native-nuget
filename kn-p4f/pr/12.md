TITLE: Fix value classes over a nullable underlying

A value class whose underlying can itself be null shipped with three bugs. A value class over `Int?` broke the whole module's build at its constructor import: the `_create` export took the has-value wire in Kotlin while the C# import said a plain `int`, so the ABI contract check failed generation. `List<Nick?>` crashed the generator as a parameter (no element cast), and as a result lost `Nick(null)` vs `null`, since the element projected to its underlying and both crossed as the null pointer. And a closed `Sticker<String?>` parameter passed a `string?` to a native import declared over a non-null `string` (CS8604).

```kotlin
value class Nick(val name: String?)

value class TreatCount(val count: Int?)

fun nicknames(): List<Nick?> = listOf(null, Nick(null), Nick("Oreo"))

fun labelOr(sticker: Sticker<String?>): String = sticker.value ?: "blank"
```

```csharp
// TreatCount constructs on the has-value wire
private static int? CreateChecked(int? count)

// each List<Nick?> element is the value class's own box handle: no handle is null
? (global::Interop.Gaps.Nick?)null : global::Interop.Gaps.Nick.NugetUnbox(elementHandle1)

// the closed Sticker<String?> parameter takes a nullable string
Native_LabelOr([MarshalAs(UnmanagedType.LPUTF8Str)] string? sticker
```

A nullable element over a nullable underlying now crosses as the ADR-228 box handle, in and out; `List<Sticker<String?>?>` is the same wire. A non-null `List<Nick>` element still projects to its underlying. This is pinned by Tier 1 cells in `Tier1NullableUnderlyingValueClassTest` (generated text plus a strict C# compile), not by an executed row; the integration rows over these shapes come with ADR-226 (`GenericValueClassGapTests`).

`scripts/verify.sh` green: IntegrationTests 3882, LeakTests 316, NativeAOT both suites (4 pre-existing skips), 0 failed
