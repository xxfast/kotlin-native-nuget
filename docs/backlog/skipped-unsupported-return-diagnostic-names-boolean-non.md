# The `SKIPPED_UNSUPPORTED_RETURN` diagnostic names "Boolean" for non-Boolean types.

> Extracted verbatim from `ROADMAP.md` (Phase 4: Rich type support) in the 2026-08-31 roadmap slim-down.

**The `SKIPPED_UNSUPPORTED_RETURN` diagnostic names "Boolean" for non-Boolean types.** `ForwardPlanSkipReason.NULLABLE.diagnosticHint()` (`forward/ForwardDiagnostic.kt:203-205`) is hardcoded to "expose a non-nullable wrapper, or a separate has-value/value pair, instead of a nullable Boolean return" regardless of the actual nullable element type, because `NULLABLE` was asserted (per the same file's own comment, `:131`) to only ever arise at the nullable-Boolean-return site. Message-wording bug only, not behavioural: the member still skips correctly with `SKIPPED_UNSUPPORTED_RETURN`. **Verified**: observed in real `kspKotlinMacosArm64` output against `Instant?`-returning members before [ADR-076](docs/adr/076-instant-mapping.md) taught the classifier about `Instant`. Predates ADR-076 and is unrelated to it; discovered only because ADR-076's failing tests were the first to run an unsupported nullable non-Boolean return through this path. **Partly done** (rode the `COLLECTION` hint fix above, one line): the false "Boolean" is gone, replaced by "instead of a nullable value at this position". Still deliberately names no type: `NULLABLE` fires at both an input and a return position and nothing populates its `detail` slot, so naming the type would need the same per-site plumbing the collection fix added. Left open for that.
