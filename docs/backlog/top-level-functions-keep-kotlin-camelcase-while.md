# Top-level functions keep Kotlin camelCase while every other position PascalCases.

> Extracted verbatim from `ROADMAP.md` (Phase 3: Basic type support) in the 2026-08-31 roadmap slim-down.

**Top-level functions keep Kotlin camelCase while every other position PascalCases.** `topLevelEntry` (`ForwardCallablePlanner.kt:531`) applies no case change (`toCName` only suffixes C reserved words, `Reserved.kt:25`; `csharpIdentifier()` only `@`-escapes C# keywords, `ForwardCallablePlanner.kt:1348`), while `objectEntries` (`:549`) and `companionEntries` (`:570`) both apply `replaceFirstChar { it.uppercase() }`, and top-level *properties* are PascalCased too (`val catBreed` → `Properties.CatBreed`). Verified against committed, compiling call sites: `Arithmetic.add(3, 4)` and `ClinicSample.patientNameLength(patient)` (camelCase) against `CatRegistry.Clear()` (an `object`, PascalCase) and `TopLevelPropertyTests.cs:10`. Deliberate enough to be commented at `IntegrationTests/MethodParameterMarshallingTests.cs:141`. Surfaced while writing [ADR-074](docs/adr/074-expect-actual-declarations.md) (Forward `expect`/`actual` declarations), whose top-level `actual fun` shapes had to inherit the existing convention rather than fix it for one declaration kind; out of that feature's scope. The already-closed item above on `object` methods called the identical inconsistency "off-idiom" and fixed it, which is the argument for closing this one too.
