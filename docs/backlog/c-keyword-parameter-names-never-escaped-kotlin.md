# C# keyword parameter names are never escaped, so a Kotlin parameter literally named `ref`, `out`, `params`, etc. generates invalid C#.

> Extracted verbatim from `ROADMAP.md` (Phase 3: Basic type support) in the 2026-08-31 roadmap slim-down.

**C# keyword parameter names are never escaped, so a Kotlin parameter literally named `ref`, `out`, `params`, etc. generates invalid C#.** `csharpIdentifier()` (`ForwardCallablePlanner.kt:1463`) `@`-escapes a C# keyword, but it is only ever applied to the method name (`ForwardCallablePlanner.kt:549`), never to a parameter name: every `parameter.name` use site in `ForwardCallablePlanner.kt`/`ForwardCirPlanProjection.kt` passes the raw Kotlin identifier straight through. A Kotlin parameter named `ref` at any planned position renders `IntPtr ref` in `Interop.cs`, a CS1001 ("identifier expected") syntax error at generation time, not a runtime failure. Found by [ADR-077](docs/adr/077-value-classes-at-ordinary-positions.md) sub-item 4's own fixture: `Patient.reassign` was originally declared `fun reassign(ref: ChartRef)`, hit exactly this, and was renamed to `referral` to keep the fixture green rather than fix the generator (out of that feature's scope). Pre-existing and general, not specific to value classes: any parameter name colliding with a C# keyword hits it, at any position on the shared callable plan.
