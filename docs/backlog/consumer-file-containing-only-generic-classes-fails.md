> Extracted verbatim from `ROADMAP.md` (Tooling & Test Integrity) in the 2026-08-31 roadmap slim-down.

**A consumer file containing only generic classes fails generation outright, because the forward ABI contract check expects `nuget_wrap_bool` (and its siblings) on the C# side but nothing emits the Kotlin `nuget_wrap_*` exports unless an ordinary class is also present.** Observed live building the `Tier1NamedSkipDiagnosticsTest.kt` receiver-diagnostic fixture ([ADR-064](docs/adr/064-forward-unsupported-declaration-diagnostics.md) position coverage): the fire cell needed a plain `Patient` class added purely to make generation succeed. Error: `Forward ABI missing Kotlin export for nuget_wrap_bool; expected nuget_wrap_bool(in bool) -> pointer`. Same gating-mismatch shape as the `needsCoreMarshal` fix [ADR-078](docs/adr/078-forward-abi-legacy-contract-coverage.md) shipped above for `nuget_dispose`/`nuget_wrap_*`, but on the generic-class axis rather than the collections/lambdas one; that fix did not cover this trigger.
