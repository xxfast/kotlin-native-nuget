# The same route's object/string parameter marshalling disposes the argument `StableRef` up to three times.

> Extracted verbatim from `ROADMAP.md` (Phase 7: Bidirectional support (C# → Kotlin)) in the 2026-08-31 roadmap slim-down.

**The same route's object/string parameter marshalling disposes the argument `StableRef` up to three times.** `CirClassTranslator.kt:2093` unmarshals a non-primitive callback argument with `NugetMarshal.FromHandle<T>(arg{i}Ptr)`, which already disposes the handle internally on read (verified: `FromHandle`'s `string` branch calls `Native_dispose(handle)` after reading), then immediately calls `NugetMarshal.Dispose(arg{i}Ptr)` again on the very same handle, a second dispose in the generated C# alone. The Kotlin side then disposes its own copy of the same `StableRef` a third time after the function-pointer `invoke()` returns (`InterfaceBridgeExports.kt:142`, unconditional whenever the parameter is non-primitive/non-enum/non-`Boolean`). Verified by reading all three sites during ADR-084 research; not reproduced at runtime (a double free on a `StableRef` may or may not crash depending on allocator behaviour, so this needs its own repro before it can be called confirmed-crashing). Discovered alongside [ADR-084](docs/adr/084-csharp-implemented-interfaces.md), which built the equivalent single-owner-single-dispose contract for its own factory route and did not touch this one.
