TITLE: Widen value class underlyings to `Char`, sealed and `<*>` (ADR-234)

A value class over `Char` or `Char?` had no record struct, so every member typed with one was a named skip. A value class over a sealed type bound at ordinary positions but not inside a `Box`, a `Flow` or a `MutableStateFlow`. `fun anySticker(): Sticker<*>` was skipped even though the same type bound as a parameter, and a non-null `TreatCount` property (over `Int?`) didn't bind at all. Now all four cross.

```kotlin
value class Monogram(val letter: Char) {
  init {
    require(letter != ' ') { "Mylo left the monogram blank" }
  }
}

value class Clue(val device: ConnectableDevice)

fun anySticker(): Sticker<*> = Sticker(7)

fun monogramOf(monogram: Monogram): String = "signed ${monogram.letter}"

fun boxedClue(address: String): Box<Clue> = Box(Clue(NearbyDevice("attic", address)))
```

```csharp
Sticker<int> sticker = StickerWidenings.AnySticker<int>(); // Sticker(7)

StickerWidenings.MonogramOf(new Monogram('M')); // "signed M"
new Monogram(' '); // throws ArgumentException, from the Kotlin `init`

using Box<Clue> boxed = StickerWidenings.BoxedClue("ee:ff");
using IConnectableDevice device = boxed.Value.Device; // NearbyDevice, "ee:ff"
```

The C# constructor of a `Char` value class now runs the Kotlin `init` check through the create export, as `CatId` does for its `String`. `Char?` rides the has-value pair with the value as a `ushort`, so `MaybeMonogram(null)` and `null` stay distinct. A star- or `out`-projected result takes a caller-supplied type parameter, the rule a star-projected parameter already had; a `TSticker` that disagrees with what Kotlin returned fails like a wrong `as T`, which is argued from the own-`T` result rather than tested. `Sticker<*>` at an interface member result still skips by name, and a nullable map key (`Map<Monogram?, V>`) stays refused. No existing export changes shape.
