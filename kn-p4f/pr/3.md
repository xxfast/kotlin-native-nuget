TITLE: Bridge a C# implementation of an interface with `suspend` and `Flow` members (ADR-232)

`IFeeder` already declared `Task<int> FeedAsync(string cat, CancellationToken)` and `KotlinFlow<string> Meals()`, but the bridge planner refused every `suspend` and `Flow` member. So you could write a C# class implementing it and never hand it to Kotlin: the build warned `SKIPPED_UNIMPLEMENTABLE_INTERFACE` and the first crossing threw `NotSupportedException`. There was also no public way to make a `KotlinFlow<T>` from C#. Now a `suspend` slot is a Begin/End pair over the C# `Task`, a `Flow` slot is an enumeration factory over the C# `IAsyncEnumerable`, and `KotlinFlow<T>.From(IAsyncEnumerable<T>)` makes one.

```kotlin
interface Feeder {
  val name: String
  suspend fun feed(cat: String): Int
  fun meals(): Flow<String>
}

suspend fun serve(feeder: Feeder, cat: String): String =
  "${feeder.name} gave $cat ${feeder.feed(cat)} scoops"

suspend fun menu(feeder: Feeder): String = feeder.meals().toList().joinToString()
```

```csharp
class Bowl(string name) : IFeeder
{
    public string Name { get; } = name;
    public async Task<int> FeedAsync(string cat, CancellationToken cancellationToken = default)
    {
        await Task.Delay(5, cancellationToken);
        return cat == "Oreo" ? 3 : 5;
    }
    public KotlinFlow<string> Meals() => KotlinFlow<string>.From(Courses());
    // ...
}

var bowl = new Bowl("Oreo's bowl");
await Feeders.ServeAsync(bowl, "Oreo"); // "Oreo's bowl gave Oreo 3 scoops"
await Feeders.MenuAsync(bowl);          // "kibble, tuna, salmon"
```

Cancelling the Kotlin coroutine cancels the token `FeedAsync` got, a cancelled C# task is a cancellation in Kotlin, and any other fault is a catchable `NugetManagedException`. A Kotlin-made `KotlinFlow` that a C# implementation just returns round-trips through the same `IAsyncEnumerable` seam, so it doesn't need a handle of its own. A `StateFlow` or `SharedFlow` slot does need a real Kotlin flow, so there's new public `KotlinMutableStateFlow<T>.Create` and `KotlinMutableSharedFlow<T>.Create`; a wrapper without a Kotlin flow behind it throws `ArgumentException` at the slot. The legacy suspend and `Flow` routes now take interface parameters, which binds a lot of members that used to skip. No source break: the members were already on `I<Name>`.
