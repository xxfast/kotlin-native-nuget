# `Tier1CinteropStub`'s hand-written `cinterop` stand-in only stubs `CFunction.invoke` for arity 0, 1 and 2.

> Extracted verbatim from `ROADMAP.md` (Tooling & Test Integrity) in the 2026-08-31 roadmap slim-down.

**`Tier1CinteropStub`'s hand-written `cinterop` stand-in only stubs `CFunction.invoke` for arity 0, 1 and 2.** `nuget-processor/src/test/kotlin/.../tier1/Tier1CinteropStub.kt:127-140` defines exactly three `invoke` extension overloads (`(ctx)`, `(arg0, ctx)`, `(arg0, arg1, ctx)`) to satisfy the ADR-084 bridge-factory call shapes the Tier 1 harness's generated Kotlin needs to compile against, deliberately not the real Kotlin/Native `CPointer<CFunction<...>>` API. This is a harness gap, not a generator bug: a Tier 1 fixture combining a suspend function with certain other callback shapes in the same generated file can require an arity the stub does not have, and the generated Kotlin then fails to compile for a reason that has nothing to do with whether the generator's output is correct. Hit while building the [ADR-094](docs/adr/094-reflection-free-generic-dispatch.md) fixture, which had to change its combination of Tier 1 test shapes to work around the gap rather than exercise the originally intended combination. Fix is to extend the stub with the missing arities (mirroring the real `CFunction`/`invoke` shapes the generator actually emits) rather than to keep routing around it per-fixture.
