# The interface route (`interfaceEntries`, `ForwardCallablePlanner.kt:~640`) has no overload numbering at all.

> Extracted verbatim from `ROADMAP.md` (Phase 4: Rich type support) in the 2026-08-31 roadmap slim-down.

**The interface route (`interfaceEntries`, `ForwardCallablePlanner.kt:~640`) has no overload numbering at all.** `exportName = "${prefix}_${name}"` with no occurrence counter and no `_$n` suffix, unlike every other route ADR-090/ADR-095 numbered. Two same-name interface methods presumably reproduce the duplicate-symbol crash those ADRs fixed elsewhere, though this has not been spiked on the interface route specifically. **Verified in source**, not reproduced by a fixture. [ADR-096](docs/adr/096-function-default-parameters.md) (superseded by [ADR-164](docs/adr/164-optional-default-parameters.md)) used to cite this as the reason the interface route synthesized no defaulted-parameter overload; ADR-164 widens the interface route's own defaulted parameters like every other route (the dispatch moved to a Kotlin-side `when (mask)`, which needs no overload number), so this gap no longer bears on default parameters, only on two interface methods sharing a name.
