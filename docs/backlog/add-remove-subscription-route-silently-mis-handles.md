# The `add*/remove*` subscription route silently mis-handles two member shapes it doesn't restrict for.

> Extracted verbatim from `ROADMAP.md` (Phase 7: Bidirectional support (C# → Kotlin)) in the 2026-08-31 roadmap slim-down.

**The `add*/remove*` subscription route silently mis-handles two member shapes it doesn't restrict for.** `InterfaceBridgeExports.kt:42-45` collects an interface's bridgeable methods with `getAllFunctions()` only, so a subscription interface with a property produces generated Kotlin the C# side never plans a slot for (no diagnostic naming why). Separately, `InterfaceBridgeExports.kt:75` hardcodes every method's `CFunction` return as `-> Unit` (and `CirClassTranslator.kt`'s matching `NugetXxxVoidCallback`/`void` delegate shape) regardless of the interface member's actual Kotlin return type, so a subscription interface with a non-Unit-returning method generates Kotlin that fails to compile (`override` return-type mismatch), again with no KSP diagnostic naming the cause. Verified by reading both files during [ADR-084](docs/adr/084-csharp-implemented-interfaces.md) research; not reproduced against a fixture. Fix by converging this route onto ADR-084's full-member slot planner (`ForwardInterfaceBridgePlanner.kt`), which already handles both shapes, or by giving each an ADR-064-style named skip.
