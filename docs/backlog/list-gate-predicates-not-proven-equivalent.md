# The C#-side list gate and the Kotlin-side export gate are two independently computed predicates, never proven equivalent

> Extracted verbatim from `ROADMAP.md` (Phase 4).

**The C#-side list gate and the Kotlin-side export gate are two independently computed predicates, never proven equivalent.** The C# side (`tracker.needsList`, fed by the CIR walk into `includesList`, `CirTranslator.kt`) and the Kotlin side (`needsListSupport`, `NugetProcessor.kt:973`, gating whether `nuget_wrap_list`/`nuget_list_add` etc. are exported at all) are computed separately; nobody has shown they always agree. A divergence in the direction "C# emits `CreateList`, Kotlin didn't export the list support functions" would not fail the consumer build like this fix's bug did: it would compile clean and throw `EntryPointNotFoundException` at the first call, at runtime, in a consumer's hands. Not introduced or worsened by this fix: the `NugetListNative` `DllImport` class was already gated on the tracker side alone, this fix only added a second, C#-emission-side gate that has the same unproven-equivalence property. Verified by source reading only, no concrete divergence found. Discovered alongside this `CreateList` gating fix, while confirming `includesList` and `needsListSupport` are not the same flag.
