# A callback invocation racing past `removeListener`/`Dispose()` can now trip `Environment.FailFast`

> Extracted verbatim from `ROADMAP.md` (Phase 7).

**A Kotlin-side callback invocation racing past `removeListener`/`Dispose()` used to run silently through whatever the runtime-built marshaller thunk still pointed at; under the [ADR-102](docs/adr/102-aot-safe-forward-callbacks.md) static thunks it can now trip `Environment.FailFast` on a freed ctx `GCHandle` instead.** The race itself (a Kotlin-side invocation delivered after the C# side has already unsubscribed and freed its `GCHandle` pins, for a stored callback or an interface bridge) is pre-existing, not introduced by ADR-102: it is the same "invocation lands after dispose" window `AddMoodListener`/`AddListener`/interface-bridge release always had. What changed is only how loud the outcome is: a `GCHandle`-pinned delegate the marshaller's runtime-built thunk still resolved (whether or not the delegate's backing state was still valid) previously either ran or quietly did nothing wrong-looking; `GCHandle.FromIntPtr(ctx).Target` on an already-freed handle inside the new static thunk is fatal. Source-read only during ADR-102 implementation, not reproduced under load; the full test suite stays green because nothing exercises the race window. Discovered alongside [ADR-102](docs/adr/102-aot-safe-forward-callbacks.md).
