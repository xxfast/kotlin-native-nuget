# Supported Features

This is the catalogue of language features the bridge maps across the Kotlin/Native ↔ C# boundary — in **both directions** — and how. For the development roadmap (including what is not yet supported) see [ROADMAP.md](ROADMAP.md). For the reasoning behind each mapping follow the ADR links in the last column.

**Direction** (the middle column of every table):

| Glyph | Meaning                                                                               |
|-------|---------------------------------------------------------------------------------------|
| `→`   | Kotlin → C#: a Kotlin feature you author, surfaced as C# (forward, code generation)   |
| `←`   | C# → Kotlin: a feature from a consumed C# NuGet package, surfaced as Kotlin (reverse) |
| `⇄`   | both directions                                                                       |

`⇄` is the target state. Where a row is one-way, the **Notes** say why — either it is **fundamental** (the reverse direction reads a compiled assembly you don't own, so some source-only Kotlin concepts can't round-trip), or it is simply **not built yet** (see [ROADMAP.md](ROADMAP.md)).

**Notes**

- **`[1]`** ← The `GCHandle` is released via `Cleaner` (deterministically via `close()` / `use {}`). C# statics land in a `companion object`, instance members on the wrapper. An instance member colliding with the wrapper's own `handle`/`close`/`cleaner` is skipped with a warning. Object return/param nullability is metadata-driven per `NullableAttribute` (`Foo` vs `Foo?`); a new wrapper is created per crossing (identity equality, no caching).
- **`[2]`** ← Overloads retain their parameter types and use signature-derived internal bridge identities.
- **`[3]`** → Object methods behave exactly like class methods (e.g. a `String` return → `string`).
- **`[4]`** ← Only public top-level, default-`int`, non-`[Flags]` enums with unique contiguous `0..N-1` values. Nullable, nested, sparse, aliased, collection, and generic enum positions are not built yet.
- **`[5]`** Two shapes share one wire format and `data class` surface. **Shape A**: exactly one state-covering constructor whose parameters define the components, in constructor order. **Shape B**: no such constructor (public settable fields and/or `set`/`init` auto-properties); components come from C# declaration order and reconstruct with an object initializer (`new T { A = a, B = b }`) rather than `new T(a, b)`, binding no constructors at all. Alternate public constructors (Shape A only) become Kotlin secondary constructors backed by out-pointer bridge slots. Instance methods and get-only non-component computed properties land on the `data class` (reconstruct-on-call: N component wire args first); static methods land in a `companion object`. A component may itself be a struct at any depth: the wire flattens it recursively, depth-first pre-order (ABI name is the `_`-joined path) while the Kotlin surface stays nested, so structural equality and `copy()` compose across the nesting; all four Shape A/B nesting combinations work, including across a Kotlin package boundary. A member whose flattened ABI arity exceeds Kotlin/Native's 22-argument `CFunction.invoke` ceiling is skipped with a `skipped_abi_arity_limit` diagnostic. Class-typed components, generic structs, structs in collections, alternate constructors, and manual (non-auto) settable properties on a Shape B struct stay deferred.
- **`[6]`** → Only reachability-driven: the backing class and its `foo_*` dispatch exports are generated only for interfaces that actually appear in a planned return position; `IFoo` itself is still emitted unconditionally. Interface-typed **parameters** accept only a Kotlin-backed `IFoo` in v1 (extracted via a shared reflective `NugetMarshal.HandleOf`); a C#-implemented `IFoo` passed to one throws `NotSupportedException`. Each interface-typed return mints a fresh handle (no identity caching, per ADR-005).
- **`[7]`** ← A different feature from `[6]`, not its other direction: here C# owns the interface and Kotlin only consumes it. An interface-typed value (return, parameter, or property) always binds as `IFooHandle`, never the concrete bound class, even when the runtime object is itself bound; no downcast, no `QueryInterface`. `ITagged : IFeedable`-style interface inheritance binds unconditionally when the base interface is itself admissible and bound. Passing a bound class at an interface-typed parameter goes through a `NugetHandleOwner` marker, the mirror of the forward direction's `NugetMarshal.HandleOf`; passing a Kotlin *implementation* of the interface back to C# is not supported (Phase 7/13, still open). Skipped and diagnosed rather than silently dropped: generic interfaces, `static`/`static abstract`/`static virtual` interface members, indexers, events, and an interface with zero admissible members.
- **`[9]`** → A top-level `actual fun`/`val` takes its generated C# static class name from the **expect's** file, not the actual's, so per-target actual files with different names don't produce two differently-named C# classes for one Kotlin declaration. `actual typealias Foo = Target` erases `Foo` entirely; every reference to it redirects to `Target`'s own C# type, with `SKIPPED_ACTUAL_TYPEALIAS_TARGET` when the target isn't itself exportable. `expect sealed class`, a generic/parameterized `actual typealias` target, and cross-module `expect`/`actual` are deferred.

Generic interfaces, generic structs, and BCL collection instantiations as Kotlin collections stay open (see ROADMAP.md Phase 10).

**`[1]`** `Map`/`Set` parameters bind only for key/value/element types the C# write side can box: `String`, `Int`, `Long`, `Float`, `Double`, `Boolean`, and object handles. An enum, `Char`, a nullable component, a nested collection, a value class, or an interface still skips with `SKIPPED_UNSUPPORTED_INPUT`.

**`[9]`** A `var` collection property's setter binds only when every component (the element for `List`/`Set`, the key **and** value for `Map`) satisfies the same `isWrappableComponent()` predicate as `[1]`, applied to `List` as well. An ineligible component keeps the property get-only in C# and emits a `SKIPPED_UNSUPPORTED_INPUT` diagnostic naming it. The getter is unconditional and has no element-type restriction; only the setter is narrowed. The collection reference's own nullability (`List<T>?`) is independent of its components' marshallability and always gets both a getter and (when eligible) a setter.

See [ADR-011](docs/adr/011-collection-type-mapping.md), [ADR-062](docs/adr/062-forward-callable-plan.md), [ADR-073](docs/adr/073-map-and-set-parameters.md), and [ADR-075](docs/adr/075-collection-property-getter-setter-independence.md).
