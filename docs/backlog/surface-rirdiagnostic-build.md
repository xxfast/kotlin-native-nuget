# Surface `RirDiagnostic` to the build.

> Extracted verbatim from `ROADMAP.md` (Phase 8: Ecosystem — consuming NuGet packages from Kotlin) in the 2026-08-31 roadmap slim-down.

Surface `RirDiagnostic` to the build. [ADR-043](docs/adr/043-bridgeable-subset-boundary.md)'s premise is "fail fast with diagnostics naming each skipped member and why". `NugetGenerateBindingsTask` now has one `diagnosticWarnings(rir)` path for reader-emitted diagnostics and Gradle-plugin-derived member-name collisions; [ADR-057](docs/adr/057-csharp-overload-sets-in-kotlin.md) also makes `error_kotlin_signature_collision` fatal while preserving warning/info severities. Remaining: this is a Gradle build-log warning only, not a structured/queryable report, and there is still no dedicated test asserting every `RirDiagnosticKind` reaches the log. **Both directions now have this gap, not just reverse:** [ADR-064](docs/adr/064-forward-unsupported-declaration-diagnostics.md) gives the forward direction its own in-memory `ForwardDiagnostic` model with the identical shortcoming (KSP-log-only, no structured report); its Alternative 4 explicitly defers a shared JSON report covering *both* `RirDiagnostic` and `ForwardDiagnostic`, sequenced after both directions emit through their own in-memory models, which, as of ADR-064, they now do
