TITLE: Bind a generic interface at every position (ADR-224)

A C# `IKeepsake<string>` could already reach Kotlin through a parameter, but every other position (a return, a getter, a property, a nullable, a collection component, a `suspend` result, a `Flow` element, a `Box<..>` argument, a lambda) still skipped with `generic declaration`. So a C# implementation Kotlin stored couldn't be read back. Two pieces were missing: a generic C# wrapper for a Kotlin-backed value that dispatches over the erased receiver, and a reflection-free way to mint a handle for an instantiation only the consumer chose. A generic interface now gets a `Keepsake<T> : IKeepsake<T>` backing wrapper, and an erased input mints through a default interface method on a per-library `INugetBridgeable<out TSelf>` marker.

```kotlin
class Trove {
  var kept: Keepsake<String> = Locket("Oreo")
  fun keep(): Keepsake<String> = kept
}
```

```csharp
using var trove = new Trove();
using IKeepsake<string> kept = trove.Kept;   // a Kotlin Locket: the Keepsake<string> wrapper
kept.Item = "Mylo";

var diary = new Diary();                     // : IKeepsake<string>
trove.Kept = diary;
Assert.Same(diary, trove.Keep());            // a stored C# value comes back as itself
```

`IKeepsake<T>` now lists `INugetBridgeable<IKeepsake<T>>` in its base list. The marker is `[EditorBrowsable(Never)]` with an `internal` member, so hand-written implementers don't change. A constrained generic interface now restates its `where` (`IPerch<T> where T : IFurry`), which adds a constraint to an interface that's already shipped. Its async members aren't skipped anymore either, so an implementer has to implement them.

Fixes two bugs on the way: a generic bridge reached only at an erased position called a nonexistent `NugetMarshal.WrapOwned` (CS0117), and a member-level `<R>` on a generic interface came out as a phantom `IntPtr Map(T)` no implementer could satisfy (CS0535). That member is now left off, as on a class.

A C# `IKeepsake<int>` read back at an `IKeepsake<string>` position throws a catchable `InvalidCastException`. Only an unchecked Kotlin cast can build that, no generated signature does.
