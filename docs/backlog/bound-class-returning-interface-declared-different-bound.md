# A bound class returning an interface declared in a different bound namespace generates non-compiling Kotlin.

> Extracted verbatim from `ROADMAP.md` (Phase 9: Reverse basic type support — C# objects in Kotlin) in the 2026-08-31 roadmap slim-down.

**A bound class returning an interface declared in a different bound namespace generates non-compiling Kotlin.** A class in package A whose method or property returns an interface bound in package B lowers the return through `nuget{InterfaceName}Value(ptr)`, but the import collector that builds the generated `{ClassName}Bindings.kt`'s import list only imports the bare interface type, not its `nuget{Name}Value` resolver function (`NugetGenerateBindingsTask.kt:4247-4249`). Every fixture built against this pipeline so far, including [ADR-085](docs/adr/085-kotlin-implemented-csharp-interfaces.md)'s `Menagerie.cs`, declares its interfaces and every class returning them in the same namespace, so the cross-package case has never been exercised. **Inferred by reading, not reproduced against a fixture.** Discovered alongside [ADR-085](docs/adr/085-kotlin-implemented-csharp-interfaces.md), pre-existing since [ADR-070](docs/adr/070-csharp-interfaces-in-kotlin.md).
