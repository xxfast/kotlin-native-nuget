# The stored-bridge survives-a-collection test proves only identity-token resolution, not a real member call through the stored bridge.

> Extracted verbatim from `ROADMAP.md` (Tooling & Test Integrity) in the 2026-08-31 roadmap slim-down.

**The stored-bridge survives-a-collection test proves only identity-token resolution, not a real member call through the stored bridge.** [ADR-085](docs/adr/085-kotlin-implemented-csharp-interfaces.md)'s `LiveKotlinGoatBridge_SurvivesACollection_AndStillResolves` (`IntegrationTests/MenagerieRoundTripTests.cs`) forces several collections, then asserts `sanctuary.featured === goat` on the Kotlin side, which exercises the `IFeedableKotlinToken` probe and the ctx `StableRef` resolution, but never dispatches an actual member call (`Describe()`, `Feed()`, ...) through the surviving bridge's function pointers afterwards. A bridge whose token still resolves but whose function pointers had somehow gone stale would still pass this test. Needs one `TestDependency/Menagerie.cs` method that calls a member on its stored `_featured` field (mirroring how `FeedAnimal`/`Introduce` already call into a freshly-crossed `IFeedable`) and a fixture assertion that calls it after the forced-collection loop.
