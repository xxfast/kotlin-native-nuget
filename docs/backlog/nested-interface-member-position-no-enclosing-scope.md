# A nested interface at a member position drops its enclosing scope

**A Kotlin `interface` declared nested inside another exported class, used at a member type position (a return, a property, a parameter), spells only `I<Simple>` in the generated C#, with no enclosing scope at all.** `ForwardBridgeTypeClassifier.kt`'s `interfaceType` helper prefixes `I` onto the *last* path segment only; it never walks `parentDeclaration` the way `nestedCsName()` does for a class or a sealed subclass. Since a nested interface, like a nested enum, is never actually declared in the generated `Interop.cs` either (there is no membership/collection path for one), the spelling is dangling today regardless: it names an interface type that was never emitted. Nothing in the tree exercises a nested interface at a member position, which is why this has gone unverified; inferred from reading `interfaceType` alongside `nestedCsName()`. Discovered alongside the nested sealed-subclass member-position fix ([ADR-009](https://github.com/xxfast/kotlin-native-nuget/blob/main/docs/adr/009-sealed-class-mapping.md)).
