# The legacy top-level two-call route (`staticLegacyTwoCall`) emits non-compiling C# for a collection parameter on a nullable-primitive-returning top-level…

> Extracted verbatim from `ROADMAP.md` (Phase 4: Rich type support) in the 2026-08-31 roadmap slim-down.

**The legacy top-level two-call route (`staticLegacyTwoCall`) emits non-compiling C# for a collection parameter on a nullable-primitive-returning top-level function.** `topLevelNullablePrimitivePlan` (`forward/ForwardCallablePlanner.kt:901`) admits any parameter whose `inputSkipReason()` is `null`, which includes a wrappable `List`/`Map`/`Set`, but `staticLegacyTwoCall` (`forward/ForwardCirPlanProjection.kt:235`) never calls the collection-prelude machinery `directCustomBody` uses: its `callArgs` is built straight from `plan.callArgument(parameter)`, which for a `BridgeType.Collection` parameter unconditionally returns `"${parameter.name}Handle"` (`:550`), a local no statement in this route ever declares. A top-level `fun f(items: List<String>): Int?` would generate a reference to an undeclared `itemsHandle`, CS0103. Verified by source reading only; no fixture in `test-library` declares this shape (a top-level function returning a nullable primitive/enum/value class *and* taking a collection parameter), which is why it has never surfaced. Discovered while auditing every collection-parameter call site for the exception-safety fix above.
