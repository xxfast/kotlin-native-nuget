# A bare `Char?` property is the same latent `packNuget` crash class ADR-080 just closed for bare `Nullable(Enum)`.

> Extracted verbatim from `ROADMAP.md` (Phase 4: Rich type support) in the 2026-08-31 roadmap slim-down.

**A bare `Char?` property is the same latent `packNuget` crash class ADR-080 just closed for bare `Nullable(Enum)`.** `hasValueFanOutInner()` has no `Char` case and `ForwardPropertyKotlinEmitter.addGetter`'s `Nullable` `when` has no `Char` branch either, so a `var tag: Char?` property would be accepted by the planner (same `isPlannable`-recurses-and-admits shape as the enum case) and then abort `packNuget` at the emitter with no route, rather than skip. **Verified by source reading only, never runtime-reproduced**: no fixture declares a bare `Char?` property. The real fix is the UTF-16-vs-ANSI width work the `Char?` item above already tracks, not a copy of ADR-080's enum branches; at minimum, closing the crash on its own (without the width fix) would need the Option-2-style named `SKIPPED_UNSUPPORTED_PROPERTY` skip ([ADR-064](docs/adr/064-forward-unsupported-declaration-diagnostics.md) machinery already shipped) rather than shipping full binding ahead of the width decision. Found during [ADR-080](docs/adr/080-bare-nullable-enum.md) research.
