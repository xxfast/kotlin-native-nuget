# A nullable constructor argument on a generic class crosses wrong, or doesn't compile at all.

> Extracted verbatim from `ROADMAP.md` (Phase 4: Rich type support) in the 2026-08-31 roadmap slim-down.

**A nullable constructor argument on a generic class crosses wrong, or doesn't compile at all.** `new Box<string?>(null)` passes a real `null` into a Kotlin constructor parameter typed as a non-null `String`, since the generic-class create-width dispatch has no nullable branch (`exports/GenericClassExports.kt:103-135` builds one `export_<cls>_create_<suffix>` per non-nullable primitive width). Worse, `Box<int?>` cannot be constructed at all: the C# ctor's `typeof(T) == typeof(int)` dispatch (`CirClassRenderer.kt:92-102`) never matches `typeof(int?)`, so every nullable value-type instantiation falls to the reflective `_handle`-field branch and throws `NotSupportedException` at the first call. Verified by source reading only, not runtime-reproduced; no fixture constructs a generic class with a nullable type argument. Discovered alongside the nullable generic-property fix above (rides [ADR-083](docs/adr/083-nullable-collection-components.md)'s null-pointer decision), while reading the rest of `GenericClassExports.kt`'s create-width family for the same bug class.
